## 一、表设计（pattern = 题型簇）

```sql
pattern(
  id          TEXT PRIMARY KEY,        -- pt+日期+hash，字符串 id
  name        TEXT NOT NULL,           -- 题型名（如「数轴上两点距离与分类思想」）
  kp_ids_json TEXT NOT NULL,           -- 挂靠考点叶 1..n —— 与考点平行互查的落点
  emphasis    TEXT CHECK(emphasis IN ('重点','难点','重难点','常规')),   -- 重难点
  freq        TEXT CHECK(freq IN ('高频','中频','低频')),                -- 考察频率
  diff_code   TEXT,                    -- 难度（与 question 同字典）
  note        TEXT,                    -- 出处注记（{"讲义":"讲二题型4"}）+ 判定线索
  status      TEXT CHECK(status IN ('现行','退役')) DEFAULT '现行',
  created_at  TEXT
)
-- question.pattern_id → pattern.id（字段已在，建表后闸上外键口径）
```

## 二、口径六条

1. **与考点平行不重叠**：考点=知识本体（教材树上的"位"），题型=考法成簇（怎么出/怎么考）；
   一个题型挂 1..n 叶，一片叶下有 0..n 题型——互查不互代；
2. **属性是教研判断，不许 LLM 自评**：初值来源分层——①讲义结构信号（题型下题量/是否进强化训练）
   ②老师人工定标（重难点/频率你最有发言权）③使用足迹现算辅助。机器只填"低置信默认"，定标动作留人；
3. **抽取零 LLM**：正则锚点（题型N：）+ 所在知识点段落定挂靠叶（借 KG note.讲义 锚点），一条命令进库；
4. **录题自动成簇**：录入线切割时题目天然落在某题型标题下 → question.pattern_id 顺手挂上，
   174 个簇随录题逐渐充实；
5. **打卡的天然出题单位**：打卡的一节=一个题型簇（老区 punchkit 的 section 本质就是它）；
   组卷 take 与 find_questions 已有 pattern 维（D-20 八维之一），表一建即通；
6. **教研属性落表合规**：重难点/频率/难度是内容属性，不违反"学情按轨现算不落表"（那条管的是学生状态）。
