# v2 架构总图（底稿=用户手绘 2026-08-17 · 三笔增补待确认）

## 一、总图：知识库是枢纽，四条产线围着转

```
                    【入】                                【出】
   ┌──────────┐  题目回流   ┌─────────────────┐   题单/母题   ┌──────────┐
   │ 每日打卡 │ ═══════════▶│                 │◀═══════════ │ 每日打卡  │
   └──────────┘   ◀─取母题─ │    知 识 库      │ ─按考点组卷─▶│ /举一反三 │
   ┌──────────┐  变式回流   │  ┌───────────┐  │              │  生产    │
   │ 举一反三 │ ═══════════▶│  │ 题库(+KG) │  │              └──────────┘
   └──────────┘   ◀─取母题─ │  └───────────┘  │   题单+答案   ┌──────────┐
   ┌──────────┐  好料入库   │  ┌───────────┐  │ ═══════════▶│ 批改流水线│
   │ 录入管线 │ ═══════════▶│  │  学情库    │  │◀═══════════ │ (可迁云)  │
   │(自动采集)│             │  └───────────┘  │  学情/错因回流└──────────┘
   └──────────┘             └─────────────────┘        │
                                     │            将来：学情×题库
                                     ▼            联合检索=定制卷
                              专项/备课取题
```

**三笔增补（我在用户手绘上加的，🔴 待用户确认）**：
1. 打卡/举一反三是**双向**的——既往库里灌（回流入库），生产时也从库里取（母题派生）＝自产自销闭环；
2. 批改流水线不只是消费者——它**生产第二类资产：学情事实**（错因/趋势/掌握），经回流箭头入学情库；
3. 知识库画成**两格**：题库（题+KG+模型+错因字典）与学情库（学员×轨的事实）。

## 二、五模块与知识库的生产/消费矩阵

| 模块 | 入（生产什么） | 出（消费什么） |
|---|---|---|
| 录入管线 | 教辅/试卷/讲义好料（人工点单+使用中随手采集）；🔴 纯计算题不录只录配方（D-9） | — |
| 每日打卡 | 出的册子题目回流 | 母题/考点组卷；考察模型 DSL 出题 |
| 举一反三 | 派生变式回流 | 母题 |
| 批改流水线 | **学情事实**（判定/错因/沉淀） | 题单+答案（认卷/判卷依据，云上走题单快照） |
| 专项/备课 | — | 按考点+学情捞题组卷 |
| **全部产线** | **判据经验**（事故/拍板→判据条目，带现行/废止生命周期） | agent 开工按线全量注入现行判据（量大后语意检索补充，D-13） |

**KG（考点/题型）是万物挂靠点**（2026-08-21 起六层树·题型可选长，映射总口径=数据结构 §2.2b）：题目←question_kp、考察模型←配方挂靠、错因←err_code_map、
批改沉淀←错因间接挂靠。考点详情页=聚合落点（挂着几题/几模型/几错因/最近沉淀）。

## 三、环境空间

| 环境 | 定位 | 里面跑什么 |
|---|---|---|
| **ai-bkb-v2**（本地生产区） | 主战场=完整知识库制造工厂 | 知识库两格 + 薄展示台 + 三条 session（调度/录入/批改）+ 工具链（~15 重写 skill + MCP + MinerU + 画图 + 模版库） |
| **批改模块空间**（v2 内自包含目录） | 🔴 可搬运单元→后期腾讯云 101 | 收件箱/批改库(九态状态机)/批改脚本/题单快照；与知识库只有两根管道（题单快照下行、学情回流上行）。🔴 v2 无"圣域"概念，库就是自己的库正常读写 |
| **ai-bkb**（老区） | 🔴 独立生态·零交互 | 学员服务独立照跑到 v2 接管后归档；过渡期不做桥不做同步，v2 不读不写老区 |
| **punch-console**（v2 内旧系统） | 🔴 冻结退役（2026-08-19 用户拍板并入 v2） | :3000 不再起；功能归 console/，数据经吃库桥入 kb.db；`知识库/资料库.db` 吃完冻结为只读冷档 |
| **备课帮 prod**（阿里云+101 机器人） | 🔴 独立生态·零交互 | 教务系统；**隔离它正是迁移目的**——v2 不调 book-server/teacher-mcp/101 教务链，不读写它的库与业务数据 |
| **飞书通道层**（v2 自己的） | 🔴 不在隔离范围（通道≠产品） | 出件推送可走飞书；**方向：批改流水线整个常驻飞书**（收卷/队列/终审/出件），展示台留作看家底面 → 总纲 Q-10/Q-13 |
| **交付面** | 出口 | 网盘/打印/飞书；渲染永远 agent 本地（模版库只存配方样张）；平台发布走用户手机 App（agent 只备料）；通道无限制——**能打开就行** |

## 四、展示台=枢纽的仪表盘（最小面）

工作台 / 题库（教材树筛选）/ 资料清单 / 批改（学员·队列九态，终审=抽屉动作对着卷面原图拍）/
录入（记录·审核台）/ 维护（知识图谱·考察模型·错因管理·判据沉淀）/ 模版库
—— 挂账+展示+终审，写动作归 agent。
