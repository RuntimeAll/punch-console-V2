## §0 一句话结论

**老区 KG 的「层级契约」（id 每 3 位一层 + 结构列承载教材元信息 + level4 为考点锚点层）值得沿用，
但「名字体例」不存在——它是四套风格拼起来的历史堆积，实测自解析率只有 73.5%、
存量物料词表对它的 resolve 命中率只有 2%~29%，且藏着 48 个整段复制出来的假叶子。**

所以推荐口径是：**沿用 ID 体系与树形契约，不沿用名字**。
名字要在迁移时过一遍清洗闸（去编号前缀、拆题型化、删重复子树），否则 v2 一开局就继承 236 组重名 + 223 个层级混装节点。

⚠️ **「1345 个 kp」这个数字不成立**：实测叶子 2781 个、level4 节点 2362 个、level4 叶子 2289 个，
没有任何一个自然口径等于 1345；在 `认知/`、`CLAUDE.md`、`ai-bkb-v2/` 全文 grep 也查不到 1345 的出处。请以本文数字为准。

## §2 命名体例 checklist（老区实际遵守的规则）

按「实测遵守率」排序。前 4 条是真规则，后 4 条是**名义规则但已破防**。

### ✅ R1　教材/年级/版本信息不进名字，进结构列（遵守率 99.9%）

2781 个叶子里含年级/教材字样的只有 2 个，且都是空壳根。
- `100004005002003` = `整式的化简求值`（**不是**「七上·整式的化简求值」）
- `500001001001` = `三角形的定义`
- `306002002001` = `被除数是0的除法`
- `903003001010` = `电流的单位`
- `905001001003` = `酸的概念`

### ✅ R2　叶子是**名词短语**，不是句子；动词只在「必须区分操作」时出现（遵守率 ~74%）

含动词的叶子仅 22%~33%，且高频动词集中在 5 个：`应用(94) 计算(88) 探究(77) 解(76) 认识(65)`。
- 名词短语主路：`矩形的定义` / `垂线段最短` / `二次根式有意义的条件` / `频数分布直方图` / `比例中项`
- 动词只在区分操作时用：`画平行四边形` vs `数平行四边形`（307006002005 / 307006002007）——
  同一个对象，动词是唯一区分位，这时才配动词。

### ✅ R3　叶子只写「知识点」，不写「题型/难度/来源/册次」（遵守率 ~97%）

含冒号或括号的题型化叶子仅 1%~7%（数学小学最高 7%）。
- 正例：`小数乘整数` / `积的近似数` / `质数的特征` / `函数值` / `余弦的定义`
- 反例（少数破防，见 §4-D）：`口算乘法：两位数乘一位数（不进位）` / `笔算除法：三位数除以一位数`

### ✅ R4　「的」是默认连接词，允许且高频（54.0% 叶子含「的」）

不追求去「的」的极简风。`有理数的加法法则` / `二次根式的性质` / `圆柱的表面积` /
`呼吸系统的组成` / `杠杆五要素`（也允许不带）。

### ⚠️ R5　叶子不带章节编号前缀（遵守率 98.8%，但**上层全面破防**）

叶子层：带任意编号前缀的只有 **33 / 2781 = 1.2%**（且这 33 个基本是「层级混装」误当叶子的章节节点，如 `九 总复习`）。
**但 level2/level3 完全相反**：level3 有 238/538 带编号（`1.1 xxx` 123 个 + `n.` 98 个 + `第N节` 17 个）。
→ 真规则应表述为：**编号只出现在章/节层，绝不出现在知识点层**。

## §3 别名机制实况

### 🔴 结论：**老区 KG 根本没有别名机制。一条别名都没有。**

证据（全库扫描 `information_schema.columns`）：

1. **`biz_subject` 无别名列**。全部 18 列 = `id / parent_id / name / level / sort / status /
   create_by / create_time / update_by / update_time / remark / mine_visible /
   subject / stage / grade / volume / edition / edition_year`。
2. **全库没有任何 KG 别名表**。搜 `column_name LIKE '%alias%' OR '%synonym%' OR '%nick%'`，
   全库仅命中 `sys_user.nick_name` 和 `sys_social.nick_name` —— 都是 RuoYi 自带用户表，与 KG 无关。
3. `V1__baseline.sql` 里唯一带 `aliases json COMMENT '已并入的近义词'` 的表是 **`biz_label_vocab`**
   （自由标签受控字典，跟 KG 不是一回事），而且**该表在实库已不存在**
   （`Table 'ai_lesson_prep.biz_label_vocab' doesn't exist`）。
4. 现存的 `biz_free_tag`（114 行）只有 `id / name / use_count / create_time` —— **也没有 aliases**。

### 3.1 那「别名」的活谁在干？两处，都很脆

**① 查询期现算：`kg_query` 的两级模糊匹配**（`teacher-mcp/backends/db.py`）

```
LIKE '%query%' 子串精配
  └─ 结果为空 → 拉全根，用「子序列匹配」兜底
     _subseq: query 的字符按序散布于 name 即算命中
     （注释原话：「有理数乘法」⊂「有理数的乘法法则」）
```

这是**无状态的**——每次查都现算，命不中就是命不中，没有任何地方沉淀「这次人工选的是哪个」。

**② 落盘期手抄：散在各册脚本里的私有映射表**

`举一反三产物/打卡/七上整式的加减打卡/_源/qbank_ingest.py`：

```python
# 节名 → 主锚（全部 resolve_kg 在 prod 实查过的真叶子，严禁编造）
KP_BY_SEC = {
    '合并同类项':       '100004004002',
    '去括号':           '100004005001001',
    '添括号':           '100004005001002',
    '整式的加减综合化简': '100004005002001',
    '化简求值':         '100004005002003',
    '整体代入求值':      '100004005002003',
    ...  # 共 16 个本地节名 → 6 个 KG 叶子
}
```

**这就是事实上的别名表**——只是它以硬编码形式存在于**一本册子的一个脚本**里，
另一本册子重来一遍。这正是「别名机制缺位」的代偿，也是 v2 必须补的洞。

### 3.2 实测：现有 resolve 对存量词表的命中率

拿老区真实存量物料的考点词表，跑 `kg_query` 同款匹配逻辑（LIKE → 子序列兜底）打 2781 个叶子：

| 词表 | 条数 | LIKE 直命中 | 子序列兜底 | 零命中 | **命中率** |
|---|---|---|---|---|---|
| 打卡册节名（整式册 `KP_BY_SEC`） | 16 | 3 | 0 | 13 | **19%** |
| 订阅特训错因七码中文名 | 7 | 1 | 1 | 5 | **29%** |
| 专项卷目录名（27 个专项） | 27 | 0 | 0 | 27 | **0%** |
| 教辅考点索引名（五上+六上） | 578 | 11 | 3 | 564 | **2%** |

**ground truth 复核**（拿 `KP_BY_SEC` 里人工确认过的映射当标答）：

| 查询词 | resolve 结果 | 判定 |
|---|---|---|
| 合并同类项 | LIKE 命中 2 个 → `100004004002 合并同类项` / `100004004003 合并同类项的实际应用` | ✅ 含标答，但**要人选** |
| 去括号 | LIKE 命中 3 个 → `去括号法则` / `去括号法则的应用` / `去括号` | ✅ 含标答，**三选一** |
| 化简求值 | LIKE 命中 2 个 → `整式的化简求值` / `分式化简求值` | ✅ 含标答，二选一 |
| **添括号** | **MISS**（0 命中） | ❌ 人工硬指到 `去括号法则的应用` |
| **整式的和与差** | **MISS**（0 命中） | ❌ 人工硬指到 `整式的加减` |

→ 即使是同一学科同一章、且人已经确认过的词，**16 个里 13 个 resolve 不到**。

⚠️ **诚实标注**：`专项卷目录名`（0%）和 `教辅考点索引名`（2%）本来就是**产品名 / 题型名**，
和 KG 的**知识点名**粒度不同，0% 属于「拿苹果比橘子」，不能全算 KG 的账。
但 `打卡册节名`（19%）是同粒度的知识点词，19% 是实打实的差。

### 3.3 KG 名字自身的可解析度（不含外部词表，纯自查）

拿每个叶子名当 query，看 LIKE 会命中几个叶子：

| LIKE 命中数 | 叶子数 | 占比 |
|---|---|---|
| **恰 1 个（唯一可解析）** | **2044** | **73.5%** |
| 2 个 | 515 | 18.5% |
| 3 个 | 70 | 2.5% |
| 4 个 | 24 | 0.9% |

→ **短名词叶子（1~2 字）是 resolve 的毒药**：`比`(311004002)、`弧`(311005004001)、
`酸`(905001001001)、`碱`、`盐` —— 这类名字放进模糊匹配里等于噪声源。

## §5 v2 自建 vs 沿用 —— 差异对照表

v2 侧现存的考点词表**不是一套，是三套**，且都跟老区 KG 不通：

| 来源 | 形态 | 例 | 规模 |
|---|---|---|---|
| `举一反三产物/_考点索引/` | 教辅题型考点，`【考点N】` + 题型化长名 | `【考点二】小数乘法基本计算其二：小数乘小数`<br>`【考点六】简便计算其五：先添加因数"1"，再简算` | 六上 353 / 五上 225 / 五下 14 |
| `订阅特训/_产线/err_kp.json` | **错因七码**，英文 slug + 2~5 字中文 + desc | `sign/符号处理`、`order/运算顺序`、`pow/乘方`、`abs/绝对值脱号`、`fracdec/分数小数`、`dist/运算律简算`、`paren/括号嵌套` | 7 |
| 各打卡册 `_源/qbank.py` | 册内自造考点码 | `U5-K1` / `M1` `MS3` `MA8` `DA14` `L12` `G7`（六上分数册 KP_UNIT: `二单元·基础计算`…） | 每册 10~90 |

**差异对照：**

| 维度 | 老区 KG（`biz_subject`） | v2 若自建（照现有三套的路子） |
|---|---|---|
| **锚定对象** | 教材目录树（册→章→节→知识点） | ①教辅题型 ②学生错因 ③册内出题配额 |
| **粒度** | 知识点（`矩形的定义`） | 题型（`简便计算其五：先添加因数"1"，再简算`）/ 错因（`符号处理`） |
| **名字长度** | 中位 7 字 | 教辅考点 15~30 字；错因码 2~5 字 |
| **编号** | 只在章/节层，知识点层不带（98.8%） | 教辅索引**必带** `【考点N】`；册内码**就是编号**（`M1`/`U5-K1`） |
| **稳定性** | 教材不改版就不变 | 错因码随专项走；册内码换册就作废 |
| **唯一性** | 全局 id（雪花式层级码），但**名字 26.5% 有歧义** | 册内唯一，**跨册必撞**（`M1` 每本册都有） |
| **别名** | **无**（查询期模糊匹配） | **无**（各册手抄 `KP_BY_SEC`） |
| **教材元信息** | 结构列 6 个（stage/grade/volume/edition…） | 靠目录名和文件路径 |
| **多学科** | 数学 1104 叶 + 科学 1677 叶，同一棵森林 | 科学走 2022 课标另一套维度（见 `科学举一反三打标` skill §6） |
| **是否可跨物料复用** | ✅ 是全系统唯一锚（题库 12265 条 `biz_question_knowledge` 挂在它上面） | ❌ 三套互不通，`err_kp` 和 `_考点索引` 之间零映射 |
| **建树成本** | 已沉没：3400 节点 / 2781 叶已建成 | 从零：光小学数学 12 册教辅索引就 ~1500 考点待整 |

**最要命的一条**：三套 v2 词表**互相之间也不通**。
`订阅特训` 的 `符号处理` 和 `_考点索引` 的 `【考点一】小数乘法基本计算其一` 之间没有任何映射，
和老区 `100002001001 有理数的加法法则` 之间也没有。
自建 = 把「三套不通」变成「四套不通」。

## §6 推荐与代价

### 6.1 推荐：**沿用 ID 体系与树契约，不沿用名字**

用户问「为什么推荐用原来的」。可验证的理由只有三条，请只认这三条：

**① 存量题库已经焊死在它上面（唯一真正硬的理由）**

```
biz_question_knowledge  12265 行（题×知识点 M:N）
  distinct question_id  12065
  distinct knowledge_id 322
biz_question.dim1_kp_id distinct 297
biz_question.subject_id distinct 231
biz_solution_model_kp   43 行（解题模型↔知识点）
biz_kg_lecture_frag     142 行（讲义片段挂 KG 节点）
```

换体例 = 这 12265 条挂载关系全部要重挂。
⚠️ **但要看清楚**：真正被用到的叶子只有 **322 / 2781 = 11.6%**。
也就是说 88% 的叶子是**建了没用**的空节点。「沿用」保住的是那 322 个，不是 2781 个。

**② 存量物料里已经硬编码了 KG 叶子 id**

打卡册脚本里到处是真叶子 id，且注释写明「resolve_kg 在 prod 实查过的真叶子，严禁编造」：

```python
七上实数的运算打卡/_源/gen_ingest_items.py:15   KP = '100003004001'
七上整式化简求值打卡/_源/qbank_ingest.py:27      KP_MAIN   = '100004005002003'
七上整式化简求值打卡/_源/qbank_ingest.py:28      KP_SECOND = '100004005002001'
七上整式的加减打卡/_源/qbank_ingest.py:32        KP_FALLBACK = '100004005002001'
```

改 id 体系 = 这些册子的复刻/续期全部断线。

**③ 建树的人工成本已沉没，且这活极贵**

3400 个节点、28 棵树的教材目录对照录入，是几十小时的人肉活。
科学 1675 个叶子尤其重（`903 八上` 一册就 493 个叶子）。

**⚠️ 而「resolve 命中率高」不是理由——实测它很低（§3.2，19%~29%）。**
谁要拿「互通方便」当理由推荐沿用，那是站不住的，数据在上面。

### 6.2 沿用的代价：继承什么

| 继承项 | 规模 | 后果 |
|---|---|---|
| 重名叶子 | 236 组 / 494 节点 | `resolve_kg` 返回多个，每次都要人选；agent 自动挂载必错 |
| 同名兄弟 | 13 处 | 同一父下二选一，靠 id 尾号猜 |
| 假子树 `906002002` | 48 个假叶子 | 挂上去的题全挂错章 |
| 层级混装叶子 | 223 个（8.0%） | 「叶子=知识点」的假设不成立，代码里不敢写死 level（`kg_query` 已经在绕） |
| 空壳根 910/911 | 2 个 | 小学科学两册有名无实 |
| 编号风格 | level2 六种、level3 四种 | 任何按名字解析章节号的代码都要写四套分支 |
| 名字内嵌号 vs id 位序错位 | 11 处 | `section_num` 过滤参数在这些节点上不可信 |
| 题型化叶子 | 冒号 24 + 括号 76 | 题型/难度污染知识点维度，DNA 打标会重复计一次 |
| 短名歧义源 | `比`/`弧`/`酸`/`碱`/`盐` 等 | 模糊匹配的噪声底噪，`比` 一个词命中 87 个叶子 |
| 超宽扁平 | 903001001 下 72 个子 | 缺一层，选考点时人肉翻 72 行 |

### 6.3 🔴 必须改掉、不能照抄的部分

迁移时**必须过闸**，按优先级：

**P0 —— 不修就是错数据**

1. **删 `906002002` 的 48 个复制叶子**，或核对教材把「2.动力机械」真内容补上。
   闸：任意两个兄弟节点的子集重合率 = 100% → FAIL。
2. **合并 13 处同名兄弟**（同 parent 同 name 必须唯一）。
   闸：`UNIQUE(parent_id, name)`。这是 v2 建表时就该加的约束，老区没加。
3. **处理 910/911 空壳根**：要么补树，要么删。

**P1 —— 不修则 resolve 永远要人选**

4. **236 组重名叶子做消歧**：跨册重名（`平均数` 在四下和八下各一）保留但**必须靠路径消歧**——
   v2 的 resolve 接口应返回 `全路径` 而不是 `name`，让「四下/平均数」和「八下/平均数」自己分开。
5. **短名叶子（≤2 字）加限定词**：`比`→`比的意义`，`酸`→`酸的概念`（905001001003 已经有 `酸的概念`，
   而 905001001001 还是光秃秃的 `酸`——这两个本来就该合并）。
   闸：叶子名长度 ≥3 字。
6. **拆掉题型化叶子**：`口算除法：两位数除以一位数` → 知识点 `除数是一位数的除法` + DNA 题型 `口算`。
   `两位数乘一位数（连续进位）` → 知识点 + 难度参数。
   闸：叶子名不含 `：` `:`；括号补语要人工过一遍。

**P2 —— 结构清理**

7. **223 个层级混装叶子归位**：`全章综合训练` / `小结与反思` / `重难专题N` / `项目化学习N`
   这些是**教辅栏目**不是知识点，v2 应该放到另一个维度（载体/栏目），不占 KG 位。
   `800 四年级奥数` 的 24 个 level2 叶子要么补层要么明确标成「专题树」另立契约。
8. **编号前缀全部从 name 剥离**，改存独立列（`seq_label` 之类）。
   `1.1 从自然数到有理数` → `name='从自然数到有理数'` + `seq='1.1'`。
   这样 §4-E 的「名字节号 ≠ id 位序」问题自动消失，六种编号风格也不用管了。
   闸：`name NOT REGEXP '^(第[ ]*[0-9一二三四五六七八九十]+[ ]*[章节单元]|[0-9]+[.、]|[一二三四五六七八九十]+ )'`。
9. **补上老区完全没有的别名层**——这是 v2 相对老区唯一必须**新增**的东西。
   现在散在 `KP_BY_SEC` 里的手抄映射、`err_kp.json` 的错因码、`_考点索引` 的教辅考点，
   都应该作为**别名/映射行**入库指向同一批 KG 叶子，而不是各活各的。
   没有这一层，§3.2 的 19% 命中率不会变好——**因为问题不在 KG 名字，在于查的人用的是另一套词**。

### 6.4 一句话交代给拍板

> **沿用老区的「骨」（id 分层编码 + 结构列 + level4 锚点层），不沿用它的「皮」（名字）。**
> 骨是资产（12265 条挂载 + 存量册子硬编码 id + 沉没建树成本），皮是负债（236 组重名、48 个假叶子、四套编号风格）。
> 迁移动作 = 原样搬 id 与树形 → 过 P0/P1/P2 三档清洗闸 → **补一层老区从来没有的别名表**。
> 别名层是关键：老区 resolve 命中率只有 19%~29%，根因不是名字起得烂，而是**产线说的话和 KG 说的话不是一种话，中间没有翻译**。
