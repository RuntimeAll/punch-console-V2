## 一、批改流水线（五步 ↔ 九态状态机）

| 步 | 干什么 | 状态机段 | 落库 |
|---|---|---|---|
| 1 收作业 | 照片落收件箱（90 秒判稳防拍一半） | 收件中→待认卷 | batch 建行、photos_json |
| 2 确定考点 | 认卷：这是哪条轨哪一天的卷（撞库；零/多命中→人指定） | 待认卷→(待人工认卷)→批改中 | batch.track_id/day_in_track，兜底自动开轨 |
| 3 批改和核对 | 整页直读+机器复核（复锚/空题×/订正对算对/放大走预算）；存疑→人终审（对着卷面原图逐题拍板） | 批改中→(待终审)→已确认 | item 逐题、feedback 留痕 |
| 4 总结归纳 | agent 写英雄卡总结（真结论非导航句）；错因沉淀（经 err_code_map 按 (考点,码) 翻译入 cause_deposit） | 已确认→待出件 | batch.summary、cause_deposit |
| 5 出报告 | 按轨渲报告（agent 本地渲染链）→出件推送（通道无限制，能打开就行） | 待出件→已出件 | batch.report_file、xq_snapshot_json |

- 待办=三个人工态（待人工认卷/待终审/故障）的过滤视图；故障就地挂起不自动重试。
- 学员统一管理：student 全档案+肖像；学情按轨现算，跨轨只并列不加总。
- 🔴 整个模块自包含（批改产线/ 目录），后期整体部署 101。

## 二、每日打卡（四步）

1. **母题定性**：确定考察范围/考点/解题方式/核心关键（挂 exam_model 或 solution_model）。
2. **选版式出初稿**：从模版库挑骨架，出第 1 天样张——🔴 **用户点头才继续**。
3. **全量铺开 20/30 天**：🔴 过程必须留档——每个考点的**生成路径 DSL、出题方式**记进 exam_model
   （保证每个考点后续都能持续再出题）；自编题全量实算过闸（六查+逐行恒等）。
4. **发布**：成品挂账 artifact（含网盘链接+小红书标题/描述等宣发字段）→上传网盘→**发布动作永远用户手机人工**。

## 三、举一反三（四步，全程血缘）

1. **确认母题**（库里有模型走快线；没有先蒸馏）。
2. **深度解析**（解题模型：触发特征→动作结论）。
3. **算子/难度/场景调配**：按「认识懂变·变一变二」模板，难度走双旋钮（tier/freq，表驱动，LLM 只匹配不自评）。
4. **生成变体**：深度解析、原题、变体**全部带血缘入库**（mother_qid + variant_op + 解析块流）；
   生成类 source_kind='model'，题库默认折叠（D-9：只有进入交付的实例才入库）。

## 四、录题（含审核等级与执行阀）

**流程**：格式确认（魔数探测分流：文字层直读/图片 OCR/手写→批改线）→ **先查相似题记录**
（match_key+近似）→ 有相似⟹照既有切割方式直接分割录入；无⟹对照 `ingest_template` 模板库，
评估是否新建模板 → 切割（块流+题干元信息抽离带账+守恒闸）→ 按等级审 → 执行阀 → 入库（草稿→promote）。

**审核等级矩阵**（复杂度×源；拍照源+1 级；手写=人工）：

| 复杂度（文字层） | 等级 | 拍照/扫描 |
|---|---|---|
| 纯文本 | L0 直入 | L1 |
| 单张配图 | L1 抽检 | L2 |
| 两图以上/表格 | L2 速审 | L3 |
| 超长+多图+跳页 | L3 细审 | 人工 |

**执行阀五条**（全过才入）：①置信度≥85% ②格式过块流校验器 ③存取同构 ④纯图题可入但必过审（或用户明说跳过）⑤必挂考点叶子。

- 选项跳号=一律人工审（不自动规整）；小问不拆（一标记一题）；例题↔练习"就近向上"配对；
  答案版与原卷版**结构同构按序对位**回填（PRD-001 实证，免 LLM）。

## 五、横切机制（所有产线共用）

- **判据注入**：agent 开工按线全量注入 criterion 现行判据（废止不注入留档）；沉淀动作=事故→判据一条龙。
- **KG 挂靠**：kp_id 必 resolve（名/别名→叶子），叶子闸拒收章级挂靠；产线词经别名表翻译。
- **渲染**：永远 agent 本地（HTML→Chrome→PDF），系统只存模版卡+样张；出件前 Read 自检。
- **skill 账单**：每次 skill 执行落 skill_log（高频稳定的操作将来优先包 MCP）。
