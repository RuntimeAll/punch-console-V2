## 一、🔴🔴 第一原则：独立生态（2026-08-17 你亲口点透的迁移动因）

> 原话：*"那边 V2 是独立生态的，不和当前产生交互。我就是希望隔离备课帮 prod 和 ai-bkb 老区，才做的迁移的。所以我才需要 skill+mcp 重组。"*

- **v2 与 备课帮 prod、ai-bkb 老区 = 三个互不交互的生态。** 迁移不是升级老区，是**另起炉灶**。
- 隔离的对象是**产品与数据**：v2 不调 book-server / teacher-mcp / 101 教务链，不读写备课帮的库与业务数据。
- v2 **不依赖**老区的目录、库、skill：要用的资产**平移进来**（拷贝+重写），绝不跨目录引用过去。
- 老区继续独立服役（学员服务不断），v2 稳定后老区归档——**过渡期两边也零交互**，不做桥、不做同步。
- 批改模块将来部署腾讯云 101 = **租那台机器跑 v2 的独立模块**，≠ 接入备课帮生态。

**🔴 隔离不含通道层（2026-08-17 用户澄清）**：
- **飞书不在隔离范围内**——它是通道不是备课帮的产品资产。v2 可以用飞书，
  且用户后续方向是**把批改流水线整个常驻在飞书里**（收卷/看队列/终审/出件都在飞书完成）→ 见 §七、Q-7 已解。
- **teacher-mcp 不迁**（用户判断：它完全绑在备课帮产品上，46 工具几乎全是 book-server 的壳）——
  v2 建自己的工具层，不做移植也不做参照复制（Q-8 已解，形态见 §十一）。

**推论（skill+MCP 重组的真正原因）**：
- 现有 skill 都长在老生态上（路径指老区、口径按老账本）——所以不是"复制过来改路径"，
  是**参照重写**：按 v2 图景绘制 v2 自己的工具层（~15 个 skill + v2 自己的工具层，只对 v2 本地库说话）。
- **teacher-mcp 整体不迁**：它是备课帮的操作壳，v2 没有 book-server 也就没有它的用武之地。
- 老件四病（你点的）：相对路径失效 / 描述错位 / 版本过老 / 重叠重复——重组时逐一清算。

## 二、为什么离开老区（四大不满，2026-08-16 原话归纳）

1. 新开 session 与调度中心不同步，几乎到用不了的地步；
2. 生产管理完全没用——只需要**一个地方挂账 + 能展示**；
3. 资料货架/生产管理页面看不懂是干啥的；
4. 批改流水线问题超多：学情必须**按考点/专项分轨**（打卡是按考点派的，分析也must绑考点）；
   终审台不知道干啥的；报告架结构非常错误。

## 三、四大关键使用场景（v2 的全部业务面）

1. **举一反三** 2. **每日打卡** 3. **讲义备课内容：录入好题/试卷/讲义** 4. **批改流水线**
（其中批改流水线=可搬运模块，后期部署腾讯云 101。）

## 四、系统形态需求

- **知识库是枢纽**（题库+KG+学情），四条产线围着转；v2 = 完整的**知识库制造工厂**
  （skill、MCP、OCR、画图工具全套进来，那边自成一套）。
- **展示台窄而精**：挂账 + 展示 + 终审，三件事之外不做；一切写动作归 agent。
- **网站给人看，agent 自主操作**（北极星语义在 v2 延续）。
- 页面结构与交互以 V2.1 走查定稿为准（老前端"不能再用了，太烂了"）。

## 五、数据与账本需求

- 🔴 **头号：学情按轨分账**——track(学员×专项, 带考点集) → batch(轨内天) → item(错因=KG kp)；
  跨轨只并列不加总；报告命名带轨。
- **题目=块流**：题和配图一起展示，展示与导出 PDF 同一结构。
- **资料一本账**：agent 挂账，页面只展示。
- **计算题存模型不存实例**：drill 不录、DSL 生成、录入装闸、存量降权不删。
- **状态外置**：批次九态状态机全链可见，三个人工态=待办的全部。
- **渲染永远 agent 本地**：系统只存模版卡+样张（模版库）。

## 六、经验与智能需求（2026-08-17 新增）

- **判断经验要沉淀、要可查看**：录题线的拆题经验、批改线的判卷依据（复锚/口径），都进「判据沉淀」；
- **错因管理**沉淀学生的错（批改后的沉淀=精华）；判据沉淀产线自己的判断——两个库；
- **经验走注入/RAG 给 agent**：走相关线时直接拿到，累计经验=后面**增速判断**的依据；
- 判据有生命周期（现行/废止），注入只取现行。

## 七、交付需求

- 交付面=网盘 / 打印 PDF / 报告出件；小红书等平台的发布动作走你手机 App（平台判重/封号风险，agent 只备料）。
- 学情报告：肯定判断禁模糊词、报告头不带学生代号、免费面只给"考得怎么样+错在哪"。
- **出件通道无限制（用户澄清）**：飞书、文件路径都行，判据只有一条——**能打开就行**。
- 🔴 **方向：批改流水线常驻飞书**（用户后续想法）——收卷（拍照发进来）、看队列、终审、出件全在飞书完成，
  展示台留作"看家底"的桌面面。这条决定 v2 要有自己的飞书通道层（不复用备课帮 bot 的业务链）。

## 十三、四条产线标准流程（2026-08-17 用户口述定调，流程 SSOT）

**① 批改流水线五步**（与九态状态机的映射）：
1. 收作业（→收件中/待认卷）2. 确定考点（=认卷：哪张卷、哪些考点→批改中）
3. 批改和核对（→待终审/已确认）4. 总结归纳（agent 总结+错因沉淀→待出件）5. 出报告（→已出件）。
配套：**学员统一管理必须做**，学员实体要非常全面（数据结构 student 已扩：档案/教材版本/服务档位/肖像+360 视图）。

**② 每日打卡四步**：
1. **母题定性**（考察范围/考点/解题方式/核心关键）
2. 选版式、出初稿确认
3. **全量铺开 20/30 天**——🔴 过程必须记录：考点的生成路径 DSL、出题方式全部留档
   （落 exam_model：每个考点都要能**持续再出题**，这是"考点出题覆盖"的家底）
4. 发布：上传网盘 + 小红书标题/描述（落 artifact 的宣发字段，不塞 styleMeta）

**③ 举一反三四步**：
1. 确认母题 2. 深度解析 3. 算子/难度/场景调配（按「认识懂变·变一变二」模板）4. 生成变体。
🔴 深度解析、原题、变体**全部带血缘入库**（mother_qid + variant_op + 解析块流）。

**④ 录题**：格式确认 → 查相似题记录 → 有则照既有方式分割录入（题干抽离+经验吸收）；
无则评估建录入模板 → 按审核等级（L0~L3×源偏移，拍照+1 级，手写=人工）决定入库 → 过五条执行阀。
正本=数据结构 D-21。

**题目标注四方向**（用户定调）：考点 / 难度 / 考察模型（🔴 可多考点）/ 标签（场景+特殊方法，
可索引、预留维度=开新 domain）。检索维度正本=数据结构 D-20。
