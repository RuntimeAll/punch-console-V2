## 一、北极星一句话

**一座越用越厚的知识库工厂**：四大场景（每日打卡/举一反三/录题/批改）每用一次，库厚一分，
下一次出品的质量高一分——飞轮不转的功能一律不建。
（源头用户原话 2026-08-18：*"我的重点是每日打卡，还有举一反三，使用频率非常高，我希望在我使用的时候
越用，我的知识库就越厚，而且对后续的备课+出题质量会直线上升。"*）

## 二、统一口径（全系统唯一坐标系，任何产线/页面/迁移不得另起）

1. **结构坐标 = 教材树**：版本→年级学期→单元→小节→考点叶；老区 id 原值保留（100 七上浙教/301~312
   人教小学/401 七下……）；私有编排（讲义讲次/页码/专题）只进注记与血缘，**不绑架结构**；
2. **考点自带教研属性**：重难点/频率/难度/描述直接长在考点叶上，与题目属性同构（"考点本身也得有，
   跟题目的属性是一样的，另一个维度的对齐"——用户 2026-08-19 对齐-001）。🔴 **不设与考点平行的
   "题型簇"实体层**——曾因讲义"题型N"标题误立一层，当日撤回（对齐-003）：那是考点簇=考点本身的考法面，
   讲义题型信息并入考点描述，不增加复杂度；
3. **题 = 一份块流**：blocks_json 存取同构，无第二载体；题号/分值属载体不属题；
4. **一切资产带血缘**：从哪来（source/prov/mother）、被谁用（足迹现算）、给谁看（挂账）；
5. **属性定标 = 表驱动 + 人工/判据**：重难点/频率/难度这类教研判断由讲义结构信号+老师定标+判据沉淀给，
   **LLM 只匹配不自评**；
6. **学情 = 按轨现算不落表**（教研属性落表、学习状态现算，两者别混）。

## 三、边界（北极星的"不做"面）

- 独立生态零交互（老区只读、备课帮 prod 零变更）；
- 不在四大场景里的能力一律先不建；
- 数据批量化一律零 LLM 机械管线（token 只花在"原料变结构化"一次）；
- 发布动作永远人工（自动化=封号红线）。

## 四、防漂移机制

1. 每张卡的「动因」必须能指回本件某一条，指不回=先修正本或不立卡；
2. 调度中心每批次收口时对照本件写一行"飞轮增量"（这批让库厚了什么）；
3. 感到漂移=随时回本件对表——本件短，就是为了随时能读完；
4. 🔴 **实践驱动开发**（2026-08-22 用户令：*"后面我们就以实践驱动开发吧"*、*"最后交付我们的是
   完整的好用的系统，在一遍遍使用中补足"*）：**先用真实需求跑一遍全链，缺什么补什么**，不预建。
   四上期末卷全流程实战当天就逼出四件真缺口（老版教材单元无枝→补枝／成品无处可看→成品速览页／
   成品散落→成品库归一／文件关联靠猜→artifact_file 硬绑），比预想的规划准得多；
5. 🔴 **三次触发规则**（同日用户立）：暂不做的能力**记账不动手**，每被"人肉替代"一次记一笔，
   **满 3 次即开工**（现行账＝PRD-007 §7 组件化二期三件，各 1 笔）——防的是两头：
   既不为想象中的需求造轮子，也不让同一件苦活反复手做第四次。
