# 知识图谱加层策略（2026-08-21 · 只出策略未开工）

> 用户原话：「感觉现在的知识图谱很奇怪，又不够深，然后还不能被拓展」「直接挂知识点下的考点，单出一层」
> 范围：**只管浙教七上这一批**，历史数据（人教老册）不整。

## 一、诊断：不是你的错觉，是三条硬伤叠出来的

### 硬伤 1：深度被砍了一层（对比老区实测）

| | 老区 `biz_subject`（考古件实测） | v2 现行 kp |
|---|---|---|
| 层级 | 1册根 → 2章 → 3节 → **4知识点** → **5细分点** | 版本 → 年级学期 → 单元 → 小节 → **考点** |
| 七上树规模 | id=100 树，含 **38 个 level5 细分点** | 102 节点，**71 片叶，无第六层** |

v2 的「考点」层 ＝ 老区的 level4 知识点层。老区那 38 个 level5 细分点（`倒数`、`移项`、
`和差倍分问题`、`将用科学记数法表示的数还原`…）**在平移时没跟过来**——所以你觉得"本地范围大、这边挂不上"，
是真的少了一层，不是感觉问题。

### 硬伤 2：树被设计成「只能宽、不能深」（死锁）

`kp.level` 有 CHECK 锁死五个值；更要命的是叶子闸 `assert_leaf_kp` 第 4 条：

```
n = SELECT COUNT(*) FROM kp WHERE parent_id = ?    # 有子节点 → 拒收
```

**一片叶只要长出子节点，它自己立刻失去挂题资格**，挂在它上面的题全变成违规。
所以现在的树在机制上就是：要么深，要么能挂，二选一——这就是"不能被拓展"的根。

### 硬伤 3：粒度错配，KG 说知识点，产线说题型

- 71 片叶装 1090 题，最重的 `绝对值的概念` 138 题、`相反数` 140 题——一片叶里全是不同题型的题；
- 而册子全按**题型**组织：绝对值六型（已知求数/最值/非负性/几何意义/分类讨论/符号商）、
  代数式求值五法、整式加减十四节名；
- 中间只能靠 `kp_alias` 203 条硬翻译。但别名是**翻译**不是**结构**：扛不住题型自己的属性
  （重点/难点/频率/难度四列现在只能挂在考点上），也答不了「这个题型有几道题、够不够出一册」。

## 二、方案：加第六层「题型」，用「就近可挂」解开死锁

```
版本 → 年级学期 → 单元 → 小节 → 考点（71 片，现状一个不动）→ 题型（新层，可选长）
```

🔴 **关键设计＝就近可挂原则**（这一条是整个方案能落地的支点）：

| 情况 | 题挂哪 | 现有数据 |
|---|---|---|
| 考点叶**没长**题型子节点 | 照挂考点（现状） | ✅ 1090 题全部合法，**零重挂** |
| 考点叶**长了**题型子节点 | 新题必须挂到题型上 | 该叶下的老题按机器映射下沉，下沉不了的留考点层并标记 |

闸的改法：从「必须无子节点」改成「**必须是所在枝的最末端**」。这样树可以**一片叶一片叶地长**，
长哪片哪片下沉，不需要全局改造，也不会一改就全库违规。

## 三、原料：不用从零建，四份现成资产

| 原料 | 规模 | 可用度 |
|---|---|---|
| `工具箱/kg/题型锚定映射.json` | 173 个讲义题型，**103 已锚定到具体叶**（带题型名+kp_id） | 🟢 直接变节点 |
| 一本通 8 专项节名 | ~30 个（绝对值六型/代数式五法/整式加减 14 节名…） | 🟢 **已出仓验证过**的题型口径 |
| `kp_alias` | 203 条产线词 | 🟢 一部分可升格成题型节点 |
| `solution_model` | 8 张解题模型卡 | 🟢 已能挂叶/节/章 |
| 老区 level5 细分点 | 七上 38 个 | 🟡 平移参考 |

去重后估计 **120~180 个题型节点**。

## 四、题的下沉：机器能干多少（实测）

| 分类 | 题数 | 说明 |
|---|---|---|
| ✅ 可机器下沉 | **260** | prov 有「讲+题型」且映射件已锚定，覆盖 **93 个题型** |
| 🟡 题型待归位 | 155 | 映射件里那 70 个未锚定题型的题，需人工判 |
| 🟡 键查不到 | 179 | 讲义题但映射件无此键（映射件有漏键） |
| ⬜ 无题型标注 | 496 | 试卷 161＋老册 228＋DSL 60＋其他，只能靠语意匹配或留在考点层 |

⚠️ **如实说**：93 个题型平均只有 2.8 道题——**题型层刚建起来时一定是薄的**。
这不是设计问题，是库存问题（PRD-003 题层没放量）。结构先立，题靠后面填。

## 五、分期与工期

### 第一期：只做计算类 17 片叶（**推荐先做这个**）
和上一轮定的「聚焦计算类」口径对齐——一本通已经出仓验证过的地盘。
- 题型来源＝一本通 8 专项节名 ＋ 落在这 17 片里的讲义题型；
- 段1 DDL 扩 CHECK＋闸改「就近可挂」＋反例（沙盘先行）：**0.5 天**
- 段2 铺题型枝（约 40~50 个节点）：**0.5 天**
- 段3 该 17 片叶下的题下沉＋验收：**0.5 天**
- **合计 1.5 天**；产出＝计算类能按题型出册、能查「这个题型有几道题」

### 第二期：全 71 片叶铺满
- 173 讲义题型全部归位（含 70 个待归位的人工判定＋补映射件漏键）；
- 260 题机器下沉、155＋179 题人审；
- **2~3 天**（agent 并行可压到 2 天）

### 第三期（可选，依赖题层放量）
496 道无标注题用语意匹配下沉；随 PRD-003 题层放量一起做。

## 六、风险与必配的闸

1. **改 CHECK ＝ SQLite 重建 kp 表**——有先例（窗I 重建 artifact 表），沙盘先行＋`kb.db.bak` 备份；
2. **叶子闸是全局公共件**（ingest_flow / model_tool / paper_tool 都调）——改前必须配正反例，
   套件全绿才落主位；
3. **UNIQUE(parent_id,name) 已经有了**（老区没有的约束，v2 建表时加的）——题型层天然防同名兄弟；
4. 🔴 **不要照抄老区的名字**：考古件实测老区 2781 叶里有 236 组重名、48 个假叶子、
   24 个冒号题型化名（`口算除法：两位数除以一位数`）——沿用它的骨（分层 id），不沿用皮。
