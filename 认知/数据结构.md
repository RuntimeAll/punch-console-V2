## 一、批改库 grading.db（5 表）

```sql
-- 学员（🔴 2026-08-17 用户点名"学员统一管理必须做，实体要非常全面"——扩全；
--       代号=现状习惯（本来就没有真名可记），不是隐私限制，将来要加什么字段直接加）
student(
  code         TEXT PRIMARY KEY,         -- 代号（现状唯一标识）：小崽子/洛天熙/小铁蛋…
  grade        TEXT,                     -- 年级
  textbook_ver TEXT,                     -- 教材版本（人教/浙教…，出题与认卷都要）
  status       TEXT CHECK(status IN ('试听','在读','暂停','结课')),
  service_tier TEXT,                     -- 服务档位（订阅特训7天/21天/一对一/打卡客户…）
  joined_at    TEXT,                     -- 入营时间
  profile_json TEXT,                     -- 🔴 肖像：学习特征/口味/注意事项（如"先看后算防硬算"、
                                         --    "计算准思维欠"），备课与出题的个性化依据
  note         TEXT, created_at TEXT
)
-- 🔴 学员 360 视图（现算不落表）：档案 + 在练轨 + 全部批次 + 报告清单 + 沉淀错因 + 交付物，
--    全部按 code 聚合——展示台学员页=这个视图，学员是批改域的聚合根。

-- 轨 = 学员 × 专项的一次征程（D-1/D-1b/Q-14）
track(
  id            INTEGER PRIMARY KEY,
  student       TEXT NOT NULL REFERENCES student(code),
  name          TEXT NOT NULL,           -- 专项名（=打卡练习名）：绝对值化简求值/七上混合运算…
  round         INTEGER NOT NULL DEFAULT 1,  -- 🔴 复训轮次（Q-14：复训=新轨，轨名展示带轮次）
  book_ref      TEXT,                    -- 册指针（artifact.id 或册目录名，回溯生产源）
  kp_scope_json TEXT NOT NULL,           -- 🔴 本轨考点集（kb 的 kp.id 数组）＝学情的分母，开轨时从题单快照算出
  status        TEXT CHECK(status IN ('进行中','已完结','暂停')),
  started_at    TEXT, finished_at TEXT,
  UNIQUE(student, name, round)
)
-- 开轨时机（D-1b）：派卷/绑定打卡练习那一刻登记开轨；收卷认到未登记的册 → 兜底自动开轨

-- 批次 = 某轨某一天交的那份卷（D-1/D-10）
batch(
  id              INTEGER PRIMARY KEY,
  track_id        INTEGER NOT NULL REFERENCES track(id),  -- 🔴 非空，没有轨的批次不允许存在
  day_in_track    INTEGER NOT NULL,      -- 🔴 轨内天号，个人流水号废除
  date            TEXT,                  -- 实际交卷日
  state           TEXT NOT NULL CHECK(state IN             -- 🔴 九态（D-10），迁移图唯一
                    ('收件中','待认卷','待人工认卷','批改中','待终审','已确认','待出件','已出件','故障')),
  state_since     TEXT NOT NULL,         -- 现态起点：队列「停留时长」由此现算
  candidates_json TEXT,                  -- 仅待人工认卷：撞库候选卷清单 [{track,day,sim}]
  note            TEXT,                  -- 机器原话（故障原因/撞库说明）
  auto            TEXT,                  -- 无人值守档位痕迹（L0/L1/L2）
  round           INTEGER DEFAULT 1,     -- 打回重批轮次
  task_ref        TEXT,                  -- 题单快照路径：题单快照/<track_id>/D<day>.json
  photos_json     TEXT,                  -- 本批卷面照片清单（收件箱相对路径数组，终审左栏直显）
  summary         TEXT,                  -- 英雄卡总结（agent 写，出件闸校验：必须真结论非导航句）
  xq_snapshot_json TEXT,                 -- 出件那一刻的轨级学情快照（D-2：报告可复现，账本以现算为准）
  report_file     TEXT,                  -- 🔴 报告=批次字段（D-3）：学员/<代号>/报告/<轨名>-D<n>-学情分析.png
  confirmed_at    TEXT, exported_at TEXT,
  UNIQUE(track_id, day_in_track, round)
)

-- 逐题判定（D-1，与现行直批口径兼容，错因记法升级）
item(
  batch_id      INTEGER REFERENCES batch(id),
  qno           INTEGER,                 -- 卷面题号
  verdict_pre   TEXT CHECK(verdict_pre IN ('√','×','?')),      -- 机器初判（?=存疑）
  verdict_final TEXT CHECK(verdict_final IN ('√','×','去掉')),  -- 终审拍板（去掉=作废不计分母）
  stem_seen     TEXT,                    -- 卷面誊写的题面（复锚判据：与题单不符按所抄算）
  answer_raw    TEXT,                    -- 末行答案原文
  lines_json    TEXT,                    -- 逐行转录（作答稿）
  note          TEXT,                    -- 存疑原因/错因备注（人话，对外禁「抄错」措辞）
  error_kp_json TEXT,                    -- 🔴 错因挂 kb 的 kp.id 数组（经 err_code_map 翻译），局部七码废除
  page          INTEGER, zooms INTEGER,  -- 在第几页照片、放大次数（放大预算审计）
  PRIMARY KEY(batch_id, qno)
)

-- 终审/打回留痕（D-4）
feedback(
  batch_id   INTEGER REFERENCES batch(id),
  round      INTEGER,                    -- 第几轮打回
  body       TEXT,                       -- 打回意见/终审改判记录
  created_at TEXT
)
```

#### ① question 主表

```sql
question(
  id            TEXT PRIMARY KEY,        -- qid：🔴 一律字符串（雪花 JSON double 截尾教训）
  -- 正文三件（🔴 老区教训：它有三份并存载体 stem_text/block_json/text_content，
  --            15674 题里 46% 一点答案都没有 —— v2 只留块流一份，答案缺失由闸拦）
  blocks_json   TEXT NOT NULL,           -- 题面块流（规范见 ②）
  answer_blocks_json   TEXT,             -- 答案，同构
  analysis_blocks_json TEXT,             -- 解析，同构
  -- 分类（🔴 值域走字典表不写死：老区 Java javadoc 写"6 类题型/3 档难度"是**过期注释**，
  --       现行字典是 8 类/4 档，照注释写代码必错；老区还并存四套题型编码）
  qtype_code    TEXT REFERENCES dict_item(code),   -- 题型
  diff_code     TEXT REFERENCES dict_item(code),   -- 难度
  pattern_id    TEXT REFERENCES question_pattern(id),   -- 🔴🔴 对齐-003 起【停用】：列保留不写值（见 ④）
  -- 来源与血缘
  source_kind   TEXT CHECK(source_kind IN ('scan','manual','model','pipeline')),
                                         -- D-9：题源类(scan/manual) vs 生成类(model/pipeline)，题库页默认只看题源类
  source_raw    TEXT,                    -- 🔴 来源原文（老区打标三件套之一）：如"2024 杭州十三中二模"
  prov_json     TEXT,                    -- 血缘：{doc,page} / {model_id,params,seed} / {mother_qid,operator}
  mother_qid    TEXT REFERENCES question(id),  -- 母题（🔴 老区注释说"SSOT 在 trace 表"是谎言：
                                         --   trace 只有 6 行、本列 5260 行 —— v2 就以本列为 SSOT，不建平行 trace）
  variant_op    TEXT,                    -- 变式算子（🔴 老区 variant_relation 存的其实是教辅栏目名"对应练习1"，不是算子，不继承那个坑）
  -- 排重与标签
  match_key     TEXT,                    -- 排重键（认卷撞库/册内查重）
  -- 🔴 标签不再是 JSON 散字段 → 一等公民走 tag/question_tag 两表（⑥），可索引可预留维度
  -- 状态
  status        TEXT CHECK(status IN ('草稿','已审','上架','退役')),
                                         -- 🔴 ingest 只入草稿，promote 才可见（老区实锤：录完看不见就是漏了这步）
                                         -- 🔴 退役=软删且**真的只软删**（老区 status 形同虚设：删题走物理 DELETE，
                                         --    留下 26 行孤儿 block —— v2 禁物理删，删块必连带）
  created_at    TEXT, updated_at TEXT
)
```

🔴 **小问口径（2026-08-18 拍板）**：例题/大题带 (1)(2) 小问时，**一个题标记=一道题**，小问留在题面块流内不拆
——与批改线题数口径、例题↔练习配对、血缘关系天然一致；组卷时一道题整体进出。

🔴 **两个刻意"没有"的字段**（老区契约层实证，v2 照办）：
- **没有 `score`（分值）**——分值属于**载体位置**不属于题（同一道题在不同卷里分值可以不同）。落 `paper_item.score`。
- **没有 `qno`（题号）**——题号只是切分锚点，位置由载体的 `ord` 承载（老区原话："原卷题号遇杂散 N. 会错位"）。
  ⇒ 这正是用户判词"题号分值要抽离出来"的落点：**抽出来不是挪个字段，是根本不进 question 表**。

#### ② blocks_json 规范 v2（🔴 直接继承老区最成熟的资产 + 补它的三个缺口）

老区规范 = `{v, rows:[{cells:[…]}]}`，块型只有 **text / image / option** 三种，有真校验器硬闸。
v2 沿用其骨架，并补上我 v1 草案漏掉的三样（都是 P0）：

```jsonc
{
  "v": 2,                                  // 🔴 补：schema 版本位（老区有 v，我 v1 草案漏了 → 将来无法演进）
  "rows": [                                // 行 → 单元格：天然支持一行多项与自动换行（渲染层排布）
    { "cells": [ { "type": "text", "md": "把两个完全一样的直角梯形拼成一个长方形（如图），" } ] },
    { "cells": [ { "type": "figure", "asset": "cceea0b6", "width": "48%", "caption": "" } ] },
                                           // 🔴 补：figure.width（老区 5467 个图块 100% 带百分比宽度，
                                           //    丢了它出纸质件全靠猜，宽图撑破版面）
    { "cells": [                           // 🔴 补：option 块型（老区 5187 块 / 1373 题、313 个选项含图）
        { "type": "option", "label": "A", "blocks": [ { "type": "figure", "asset": "f01", "width": "22%" } ] },
        { "type": "option", "label": "B", "blocks": [ { "type": "figure", "asset": "f02", "width": "22%" } ] }
      ] }                                  // ⇒ 用户判词"选项结构化且可自动换行"在这条规范里天然成立：
                                           //    数据层一项一 cell（结构化），排布交渲染层按行流式换行
  ]
}
```
- `text.md` = Markdown + 内联 `$LaTeX$`（老区口径，继承）；表格走 GFM，🔴 **前后必须空行**（老区 121 处病根）。
- 🔴 **存储形态定稿=「第三条路」**（2026-08-18 实测拍板，材料=考古/格式方案-拍板材料.md）：
  **md 存取同构做骨架**（一份 md+$LaTeX$，存什么用什么，无出库转换层）+ **块级 `role` 枚举**
  （`role: '题面'|'答案'|'解析'|'点拨'|'栏目'`，标"这块是什么"，不做字符级 marks）。
  实测依据：损坏率大头在切割期不在存储形态（44.65%→14.98% 全靠改切割）；marks 层体积+28.8%、
  67 行永久转换纪律、无回程、SQL 闸破，而其招牌优势被证实是测试批次超采造出来的。
  **两个必做配套**（不做则第三条路不成立）：①切割期填空归一化（w:u 空白无条件归一——实测做了它损坏清零）
  ②MathType OLE 处理（剩余损坏 94% 来自它；本讲义系列实测 0 MathType，此债挂账后置，遇到含它的书再还）。
- 🔴 **必须有校验器**（照老区 `BlockJsonValidator` 做成入库硬闸）：块型白名单、option 标号连续、figure.asset 必存在、
  width 合法、text 非空、GFM 表前后空行。**不许"注释说了算"，一律闸说了算。**
- 🔴 **table 块内部 schema 定稿（2026-08-18 补，console 真库页上报两处口径打架后定死）**：以入库闸
  `工具箱/库/gates.py` 的口径为准——`{"type":"table", "md": "<GFM 全表>"}` **或**
  `{"type":"table", "rows": [行][格][块列表]}`（格=块列表，禁拍平成字符串：拍平必丢格内图）。
  console `mock/types.ts` 的 `CellTable {cells:[{md,isHeader}]}` 是原型期旧形状，随 mock 退役（批次⑤）；
  真库页渲染兼容读、但**写侧只认闸的形状**。表头位：结构化形态首行=表头（教辅表格惯例）。

#### ③ 考点绑定（🔴 老区最危险的那个坑，必须装闸）

```sql
question_kp(
  question_id TEXT REFERENCES question(id),
  kp_id       TEXT REFERENCES kp(id),
  is_primary  INTEGER DEFAULT 0,         -- 主考点恰一（闸保证）
  anchor_json TEXT,                      -- 🔴 继承老区 kp_anchor：{stage, fallback, confidence}
                                         --    ——记住"这个挂靠是怎么来的、有多可信"，低置信进审核台
  PRIMARY KEY(question_id, kp_id)
)
```
🔴 **叶子闸（v2 新增硬约束）**：老区 `dim1_kp_id` 的注释写"挂叶子"，**实测 62% 挂在章级**（322 个被用考点里 108 个有子节点）。
这直接威胁 v2 头号目标「学情按考点分轨」——**分母是考点集，挂章级就等于分母失真**。
⇒ 入库闸：`kp_id` 必须是叶子（`NOT EXISTS(SELECT 1 FROM kp WHERE parent_id=?)`），违例拒收不静默。

#### ⑥ 标签体系（D-19，2026-08-17 用户定调）

题目的标注共 **4 个方向**：**考点**（question_kp）、**难度**（diff_code）、**考察模型**（pattern/model 挂靠）、
**标签**（本节）。标签=场景与特殊方法这类**不成树、不定量**的维度，一等公民、可索引、**预留可拓展**：

```sql
tag(
  id     TEXT PRIMARY KEY,
  domain TEXT NOT NULL,                  -- 🔴 标签域：'场景' | '方法' | '思想' | '图形特征' | …
                                         --    预留 = 随时开新 domain，零改表（这就是"预留维度"的实现法）
  name   TEXT NOT NULL,
  status TEXT CHECK(status IN ('在用','停用')),
  UNIQUE(domain, name)
)
question_tag(question_id TEXT, tag_id TEXT, PRIMARY KEY(question_id, tag_id))
```

**审核等级矩阵**（复杂度 × 源，等级=要不要人看、看多细）：

**入库执行阀（五条硬闸，全过才入）**：
1. **置信度 ≥ 85%**（低于即滞留待审，不许静默入）；
2. **格式清晰**：块流过校验器（BlockJsonValidator 口径：块型白名单/选项连续/asset 存在/GFM 表前后空行）；
3. 🔴 **存取同构**：存进库的格式=直接使用的格式，同一份 `blocks_json`（含 $LaTeX$ 内联公式）
   展示/导出/交换直接吃，**没有第二种存储形态、没有出库转换层**（所见=所存=所印）；
4. **纯图片题面可入**，但必须过审——或用户明确说跳过审核才免；
5. **每题必挂考点**（KG 叶子闸，见 ③）——挂不上就不入库，绝不裸题入库。

## 三b、🔴 与备课帮互通：`question-exchange/v1`（D-17，2026-08-17 用户点名"两者后期可以互通"）

**定位**：**交换格式，不是合库**。两边各自独立跑（运行时零交互不变），需要时把**一道题的完整描述**导出/导入。

```jsonc
// 信封
{ "contract": "question-exchange/v1",
  "from": "v2" | "beikefang",
  "exported_at": "…",
  "items": [ {
    "ext_id":    "对方系统的 id（原样带回，便于回执与去重）",
    "blocks":    { "v":2, "rows":[…] },        // 题面块流（双方共用的骨架）
    "answer":    { … }, "analysis": { … },
    "qtype":     "选择题",                      // 🔴 字典码一律传**中文标签**不传码值（对方字典表不同）
    "difficulty":"提升",
    "kp_names":  ["有理数混合运算"],            // 🔴 考点**绝不传 id**：两棵 KG 树 id 不通，
                                               //    一律按名字双向 resolve，对不上就红（不猜不静默挂）
    "source_raw":"2024 杭州十三中二模",
    "assets":    [ { "ref":"f01", "sha256":"…", "bytes":"<base64 或随包文件>" } ],
                                               // 🔴 图必须搬字节：路径/OSS 地址跨系统一律失效
    "match_key": "…", "free_tags": [ … ],
    "prov":      { "mother_ext_id":"…", "variant_op":"…" }
  } ] }
```

**十条互通纪律（每条都有老区实锤）**：
1. 交换单位=一道题的完整描述（题面+答案+解析+归属+元信息+血缘），不传库内主键关系；
2. **一切 id 传字符串**（雪花 double 截尾）；
3. **考点走名字 resolve，不传 id**；对不上进人工映射队列，绝不静默挂到章级（呼应叶子闸）；
4. **字典传中文标签**，落地方按自己字典翻译；翻不出的进隔离不猜；
5. **图搬字节 + sha256 校验**，落地方重新入 asset 表拿本地 hash；
6. `blocks` 双方共用骨架（text/figure/option/table），**块型白名单外的一律拒收**；
7. 落地方**必过自己的校验器**（老区 `format` 端点有 `degraded:true` 静默降级的坑——v2 侧不接受降级，降级即拒）；
8. **导入一律落草稿**，人工/闸 promote 后才可见（与内部录入同一条纪律）；
9. **选项标号不自动规整**（老区会规整→"是否漏抽"变得不可验证；v2 保持如实报 FAIL，见需求总纲 Q-15）；
10. **有损点必须在回执里列明**（已知 9 处：图宽百分比基准、老区三载体差异、无答案题、字典无对应、
    考点名体例差异、老区物理删除留孤儿、free_tag 计数不可信、题型四套编码、分值归载体不随题走）。

**⇒ 因此产生一个待拍板（需求总纲 Q-17）**：v2 的 KG 考点**命名体例是否与老区对齐**？
对齐 = 互通时 resolve 命中率高；不对齐 = 每次交换都要人工映射表。我倾向对齐（成本只在建树时）。

## 三c、D-20 找题检索模型（2026-08-17 用户定维度）

**混合检索三层**：①精确过滤（SQL：难度/状态/来源类/教材版本——🔴 难度是准确查询不进向量）
