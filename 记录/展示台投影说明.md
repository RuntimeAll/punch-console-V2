# 展示台投影说明（punch-console :3000 转任只读手机展示台）

> 立于 2026-08-20 收尾战役·线1。
> 一句话：**punch-console 代码零变更**，靠一个「投影库」把 kb.db 的数据摆成它认识的样子，
> 它就活过来当手机展示台用；投影库是下游，随时可整个重建。

---

## 0. 它是什么 / 不是什么

| | |
|---|---|
| **是** | 手机上翻资料的**只读**橱窗：112 份资料的泳道/体检灯、网盘链接与提取码、成品 PDF 在线看与下载、配图缩略图与保存 |
| **不是** | 录入口、编辑台、事实源。任何真改动都在 kb.db，走 `:4300` 展示台与 agent |

数据流**单向**，只有这一条：

```
知识库/kb.db（活·事实源）  ─┐
                            ├─→ 工具箱/桥/投影同步.py ─→ 知识库/资料库-投影.db ─→ punch-console :3000
知识库/资料库.db（冻结存档）─┘        （零 LLM·幂等·重跑全量重建）
```

## 1. 同步命令

```powershell
python D:\workplace\ai-bkb-v2\工具箱\桥\投影同步.py
```

- **幂等**：重跑 = 删掉投影库整个重建。没有增量、没有 upsert、不留脏行。
  连跑两次六张表逐行哈希一致（已验）。
- **上游只读**：kb.db 与 资料库.db 一律 `mode=ro` 打开，物理上写不进去。
- 跑完自带自检：五表行数对账 + 守恒打印 + 每条产物指针验文件在盘 + FTS 抽查。
  **自检有红项时退出码 = 1**，别忽略。
- 换落点调试：`--out 某路径.db`。

🔴 **kb.db 数据一变（挂账、出卷、改宣发字段），展示台不会自己跟——必须重跑本脚本，然后重启服务**（见 §2）。

🔴 **重跑前必须先停 :3000**。脚本是"删掉重建"，而服务开着时 better-sqlite3 攥着投影库的文件句柄
（进程内单例），Windows 下正被占用的文件删不掉，脚本会停在
`[X] 投影库正被占用，删不掉` 并给出停服命令。**正确顺序：停服 → 跑同步 → 起服。**

## 2. 起服 / 重启

```powershell
cd D:\workplace\ai-bkb-v2\punch-console\web
node node_modules\next\dist\bin\next start -H 0.0.0.0 -p 3000
```

探活（本机有代理，必须 `--noproxy`）：

```powershell
curl.exe -s -o NUL -w "%{http_code}" --noproxy "*" http://127.0.0.1:3000/library
```

🔴 **换库/重跑同步后必须重启进程**：better-sqlite3 是**进程内单例连接**（`src/db/client.ts` 把句柄挂在
`globalThis` 上），库文件被替换了它还攥着旧句柄，页面会一直显示旧数据。重启 = 唯一生效方式。

停：

```powershell
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Where-Object { $_.CommandLine -like '*next*start*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

### 🔴 为什么不用仓里的 `serve-v2.ps1`

它写的是 `pnpm exec next start`。**本机跑不通**：pnpm 每次 `exec` 前会做依赖校验
（`runDepsStatusCheck`），判定 node_modules 与 lockfile 不一致就自动 `pnpm install`，
而 better-sqlite3 没有对应本机 node 版本的预编译包，会退回 node-gyp 从源码编译 —— 本机没装
Visual Studio C++ 工具链，必然失败，服务起不来。

绕开办法就是上面那条**直接用 node 调 next**（等价于 `next start`，只是不套 pnpm 那层）。
`serve-v2.ps1` 是冻结仓的文件**不改**；已装好的 `node_modules` 本身是好的
（`node -e "require('better-sqlite3')"` 正常，生产 build 也正常出）。

> 首次或代码变更后需要重新 build（同样绕开 pnpm）：
> `node node_modules\next\dist\bin\next build`

## 3. 🔴 人工态会被覆盖（用之前先知道这条）

punch-console 全站**只有一个写端点**：`POST /api/doc-state` —— 详情页那个「标为在售 / 待整理 / 撤回」按钮，
改的是投影库的 `doc.人工态`。

**它写进的是投影库，下次同步就没了。**

所以：

- 页面上点「标为在售」= **只是本地临时标记**，不是入账。
- 真要改上架状态，走 kb.db 的 `artifact.sale_state`（`工具箱/挂账/artifact_tool.py`，或 `:4300` 展示台）。
  同步时 `doc.人工态 ← artifact.sale_state`，那才是事实源。

几条要记住的：

- **id 是重新分配的整数**。punch 的 `doc.id`/`question.id` 是 `INTEGER PRIMARY KEY`（rowid 别名），
  页面还拿 `Number(id)` 解析，kb 的字符串 id（`A2026…`/`q2026…`）塞不进去。
  新册 doc id 从 **90001** 起、新题 id 从 **1000001** 起，按确定序分配（幂等）。
  原始 artifact id 存在 `doc.备注` 的 JSON 里，要回查看那里。
- **9 行退役件标「停售」**（试卷复刻子集版 6 + 旧平行卷 3）。不是删掉：PDF 还在盘上、paper 还在库里，
  投影要能对上 kb 的 112 行；「停售」泳道正好是"退了役的旧件"那一档，默认也不跟现役件混在一起。
- **新册实算 = 有答案判绿、无答案留空**（本批 583 条全部有答案 → 全绿）。绝不按"跑通了就绿"猜。
- **配图类型用「页图」不用「图A/图B」**：发布包那批图是单号首发、没有 A/B 两版。
  标成 `图A` 的话手机端（默认 B 号）会显示"这本还没有 B 号的图"——图明明在盘上却看不见。
- **`doc.源文件路径` 已改写成 v2 内的产物目录**（取本册产物的公共父目录，109 册）。
  原值指老区，在 v2 工作区外，点开一律 403，留着就是坏指针。

### 宣发 note → material 投影（2026-08-20 调度中心裁决③）

发布包这类册子的文案是「发布物料」skill **直接写进 `artifact.note`** 的，没走 kb 的 `material` 表。
不补的话详情页「物料 0 · 还没有发帖物料」——文案明明齐了却一个字看不到，
而展示台存在的意义就是**手机上把文案复制走去发帖**。

**触发条件**（通用规则，不是给这三张写死的）：v2 新册 + `material` 表无行 + `artifact.note`
含 `标题候选/正文/标签/商品描述/网盘分享语` 任一非空。当前命中 **3 张发布包**。

| punch 列 | 来源 |
|---|---|
| `账号` / `is_active` / `burned` | 固定 `A` / `1` / `0`（试卷类单号首发） |
| `标题` | `note.标题候选[0]`，**去掉 "1. " 这类编号前缀**（候选编号是给人挑用的） |
| `正文` | `note.正文` |
| `话题词` | `note.标签` 拆词后**去掉 `#` 存裸词**。🔴 页面渲染时自己补 `#`（`material-switch` 里 `#{t}`），存带 `#` 的会渲成 `##初一数学`；复制钮输出的也是裸词空格分隔（小红书要在 App 里逐个选，带 `#` 粘过去不成话题） |
| `商品描述` / `网盘分享语` | 同名字段直取 |
| `风格种子` | 固定 `宣发note投影` —— **material 表没有备注/来源列，这个标记只能落在风格种子**，认它就能把投影行与真 material 行分开 |

🔴 缺哪个字段留空，不硬造。

实测：`/api/file` 拿老区路径请求返回 **403 路径不在工作区内**，闸是硬的。

### 🔴 语意 sidecar：这条是主动断的，不是本来就断的

`src/db/paths.ts` 的缺省值指向老区
`D:\workplace\ai-bkb\codeplace-O\punch-console\embed\.venv\Scripts\python.exe`，
而**那个 venv 在盘上是真实存在的**。不管它的话，`/questions` 页一旦带查询词，
Node 就会 `spawn` 老区那个 python 解释器跑老区那份 `embed.py` —— 这是**执行老区**，
撞第一原则「独立生态零交互」。

所以 `.env.local` 额外把这两个变量指到 v2 自己的 embed 目录：

```
PUNCH_EMBED_PY=D:\workplace\ai-bkb-v2\punch-console\embed\.venv\Scripts\python.exe
PUNCH_EMBED_SCRIPT=D:\workplace\ai-bkb-v2\punch-console\embed\embed.py
```

v2 侧 `embed.py` 与 `models/` 在，**`.venv` 没建** → `probeSidecar()` 判"未就绪" →
检索自动降级成纯 FTS + 考点过滤，页面把「语意轴未就绪」写在脸上，不炸页。
这正是想要的行为，且零老区执行。

> 想把语意轴用起来：在 `punch-console\embed\` 下建 venv 装依赖即可，
> 模型权重（`embed/models`）已经在 v2 这边，不用动老区。
