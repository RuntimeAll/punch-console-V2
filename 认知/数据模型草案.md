## 一、批改域（分轨账本）——头号重构

### 老账本为什么烂（审计实锤，四条病灶）

1. **批次键 = (学员, 个人第N次)**：`batches UNIQUE(student, day)`，键里没有任何册/专项维度；
   `task_id` 列 08-11 就加了但**从未写入（15/15 全 NULL 的死列）**——批改事实不能自证属于哪本册。
2. **「天号」语义已被摊坏**：day 是跨专项连续的个人流水号——洛天熙同一天交两条线的卷，
   被编成 day=1（有理数）和 day=2（整式的加减），「第02天」不是任何一条线的第 2 天。
3. **学情.json 单文件单轨**：book 是学员级唯一标量；洛天熙的整式批次**实证混入**有理数册的
   days 序列，per_kp 被硬压进有理数的 7 码词表（全按 dist 记）——这就是你说「完全不行」的现场。
4. **词表是一册的词表被当全产线常量**：err_kp.json 七码（sign/order/pow/abs/fracdec/dist/paren）
   全是有理数混合运算的错因分类；进步曲线/过关状态机遍历全部 days 无轨过滤，
   两轨并行时 A 轨的全对天会给 B 轨同名码续 streak。

### 老账本里能白捡的零件（不用新发明）

- `tasks` 表**早就有全部分轨维度**：date / line（线名）/ book（册目录）/ day（**该线第几天**）/ sheet（题单路径）；
- 工厂侧 `grading_task_map → sku → sku_item(ord=卷面题号) → question → question_kp` 已能从
  task_id 完整推回 册/专项/线内天/真 KG 考点；
- `err_code_map(kp_id, err_code)` 已是「产线错因码 → KG 考点」的现成翻译范式。

**⇒ 分轨不是新建维度，是把批改事实接上早已存在的 task 链。**

### D-1 🔴 核心账本五表（批改库 grading.db，自包含可迁云）

```sql
-- 学员（代号=现状唯一标识；08-18 拍板：代号制不是限制，本来就没有真名可记）
student(code TEXT PK, grade TEXT, note TEXT, created_at)

-- 轨 = 一个学员的一个考点/专项征程（如「七上混合运算」「绝对值化简求值」）
track(
  id INTEGER PK,
  student TEXT NOT NULL REFERENCES student,
  name TEXT NOT NULL,              -- 专项名（展示用）
  book_ref TEXT,                   -- 册指针（sku_id 或册目录名，回溯生产源）
  kp_scope_json TEXT,              -- 🔴 本轨考点集（KG kp_id 数组）——学情的分母，开轨时从题单快照算出
  status TEXT CHECK(进行中|已完结|暂停),
  started_at, finished_at,
  UNIQUE(student, name)
)

-- 批次 = 某轨的某一天交的那份卷
batch(
  id INTEGER PK,
  track_id INTEGER NOT NULL REFERENCES track,   -- 🔴 非空。没有轨的批次不允许存在
  day_in_track INTEGER NOT NULL,                -- 🔴 轨内天号（=tasks.day 语义），个人流水号废除
  date TEXT,
  state TEXT,                                   -- 🔴 九态（合法值与迁移图=D-10），旧四态废除
  state_since TEXT,                             -- 现态起点：队列页「停留时长」由此现算
  candidates_json TEXT, note TEXT,              -- 待人工认卷的候选卷清单 / 故障与撞库的机器原话
  auto TEXT, round INTEGER DEFAULT 1,
  task_ref TEXT,                                -- 题单快照指针（见 D-5 云部署）
  confirmed_at, exported_at, report_file,       -- 🔴 报告是批次的字段，不是独立世界
  summary TEXT,                                 -- 英雄卡总结（agent 写，出件闸校验）
  UNIQUE(track_id, day_in_track)
)

-- 逐题判定（与现行直批口径完全兼容，只改错因记法）
item(
  batch_id, qno, verdict_pre, verdict_final, stem_seen, answer_raw,
  lines_json, note,
  error_kp_json,     -- 🔴 记 KG kp_id（经 err_code_map 翻译），不再记局部七码
  page, zooms, PRIMARY KEY(batch_id, qno)
)

-- 终审/打回留痕（照抄现行 feedback 语义）
feedback(batch_id, round, body, created_at)
```

### D-2 🔴 学情 = 按轨现算，不再落学员级单文件

- **学情视图（轨级）**：趋势曲线、考点覆盖、过关状态机——全部只遍历本轨的 batch/item；
  分母 = `track.kp_scope_json`（本轨考点集），别的轨的码进不来也串不走；
- **学生档案（跨轨汇总）**：各轨一行（轨名/进度/正确率/状态），只做并列展示，绝不把两轨数字加总成一个%；
- **出件快照**：报告导出那一刻把该轨学情算一份快照存进 batch（报告可复现，账本仍以现算为准）；
- 老 `学情.json` 退役为迁移原料（见 Q-2）。

### D-3 🔴 报告归属与命名

- 报告 = `batch.report_file`，展示按 学员 → 轨 → 天 树状组织（"报告架"页面概念废除）；
- 文件命名带轨：`<代号>/报告/<轨名>-D<轨内天>-学情分析.png`（老命名「第0N天」的串义风险 #7 就此销案）；
- 报告头 = 轨名（不再有"取不到就回落学员级旧册名"的兜底——取不到就不出件，宁停不错）。

### D-4 终审 = 批次上的一个动作（概念降格）

- 数据上没有"终审台"实体：`state=待终审` 的批次出现在待办里，人逐题定 verdict_final → 确认 → state 前进；
- 打回=feedback 插行+state 回退，与现行审核库.py 语义一字不差（圣域原语平移，见蓝图期2）。

### D-1b 轨的开法（用户 2026-08-17 确认语义）

> *"新的学员的考点打卡练习吗？绑定新的打卡练习的时候就是新的轨道了，而且是不同的考点练习。"*

⇒ **派卷/绑定打卡练习的那一刻 = 开轨**：轨名取该练习的专项名，`kp_scope_json` 取该册的考点集。
一个学员同时可有多条在练轨（不同考点各一条），互不串账。收卷时认到没登记的册 → 兜底自动开轨。

### D-5 🔴 可迁云边界（你拍板的：批改流水线后期部署腾讯云 101）

批改模块 = **一个目录自包含**：`批改产线/{grading.db, 收件箱/, 学员/, 脚本/, 题单快照/}`。
- 🔴 开轨/建 task 时把题单 JSON **快照进模块**（`题单快照/<track>/<day>.json`）——
  云上批改不依赖工厂库连接（审计证实现在 config.py:39 跨线直连工厂库，上云即断，必须切快照）；
- 一切路径相对模块根（审计证实圣域 47 个 py 已全是相对推导，白捡）；
- 与外界只剩三条口：收件（文件落收件箱）、出件（报告文件+推送）、学情回流（batch/item 只读导出给工厂）。

## 六b、D-9 🔴 计算题：存模型不存实例（2026-08-17 用户点出）

**病**：纯计算题（口算/竖式/脱式/简算 drill）可由随机算子/表达式树 DSL 零 token 生成，
录入一道却要几百上千 token；实例检索价值≈0，还灌水污染向量检索与排重空间。库里已录了大量。

**原则**：计算题在库里的形态=**考察模型（配方：参数域+难度旋钮+DSL 指针）**，不是题目实例。

**三档处理规则（录入侧）**：
| 来源 | 处理 |
|---|---|
| 外来教辅的纯计算题 | **不录题**。认它属于哪个考察模型：已有→登记覆盖即可；没有且题型有价值→建模型（把题变配方）；不值得→跳过 |
| 自产 DSL 生成题 | **只有进入交付册的实例才入库**（认卷 match_key 撞库/批改题单/已售排重都需要它），必带 `prov.type='model'` 血缘 |
| 计算外壳但有情境/图/结构的题（应用题、图形计算、规律探究） | 照录——那是内容不是 drill |

**机器闸（不靠自觉）**：录入闸加「drill 检测」——`classify_stem` 判型资产现成（录书管线已磨过
"叙事题不判 drill"的误报判据）；命中 drill 且无 model 血缘 → 拦下（红灯或黄灯人审说理由）。

**存量处理**：已入库的生成类计算题**不删**（删了断认卷与排重），但：
① 补 model 血缘（能补的补齐）；② 检索层降权/默认过滤——题库页加「题源类/生成类」开关，
默认只看题源类（scan/manual），生成类（model/pipeline）要看手动开。

## 六c、D-10 🔴 批次九态状态机（2026-08-17 用户点名"状态外置明确"，已实装进 V2.1 队列页）

`batch.state` 的九个合法值与唯一迁移图（🔴 标"人"的三格=待办的全部内容）：

| 状态 | 推进者 | 停留原因 | 出口 |
|---|---|---|---|
| 收件中 | 系统 | 照片落收件箱，90 秒判稳 | →待认卷 |
| 待认卷 | 系统 | 排队等编排器（WIP=1） | 命中→批改中；零/多命中→待人工认卷 |
| 待人工认卷 | 🔴人 | 题面认不出是哪张卷 | 指定→批改中 |
| 批改中 | 系统 | 无头 session 判卷+机器复核 | 全绿→已确认（静默）；存疑→待终审 |
| 待终审 | 🔴人 | 逐题 √/×/去掉，可打回 | 确认→已确认；打回→批改中（round+1） |
| 已确认 | 系统 | 判定定稿 | →待出件 |
| 待出件 | 系统 | agent 总结→渲报告→推送（v2 补的自动收尾） | →已出件 |
| 已出件 | 终态 | 报告挂批次 | — |
| 故障 | 🔴人 | 异常就地挂起不自动重试 | retry→回原状态 |

收卷录入=队列页上的动作（弹窗），不是独立页面；待办=三个🔴态的过滤视图，不是独立实体。

## 六g、D-13 🔴 判据沉淀（2026-08-17 用户点名：录题也要经验沉淀、流水线判断依据要保存可查、走 RAG 注入给 agent）

**与错因的分界**：错因管理沉淀**学生**的错（挂考点）；判据沉淀**产线自己**的判断经验（挂产线）——
录题怎么拆、批改怎么判、出题怎么防坑。每条来自一次真实事故或拍板。

```
criterion(id, line 录入|批改|出题|渲染, scene 触发场景, rule 怎么判, why,
          source_ref 来源事故/正本, status 现行|废止, superseded_by, created_at)
```

- **注入两档**：①开工注入——agent 领某线任务时**按线全量注入现行判据**（百条量级全量比检索稳，不漏）；
  ②量大后语意检索补充（复用 codeplace-AI 资料 RAG 基建，不新造）。
- **生命周期闸**：经验会被推翻（实例：TextIn 退场、乱序闸降级）——废止不删、带替代链，**注入永远只取现行**。
