# 出卷流水线 —— 配方驱动的成批出卷（实例正本=产物/验收/浙教出卷/全链实例总结.md）

> 2026-08-20 窗G 浙教出卷战役（10 套 20 PDF 全绿）打通此链，PRD-008 段① 转正为本 skill。
> 与「每日打卡」的区别：打卡册是 N 天×一天一页的**连续练习**；本 skill 出的是**一张完整试卷**
> （卷头满分/时长/评分表/密封线、选择填空解答三大题、逐题分值守恒）。

## 🔴 铁律（写死，不是可选项）

1. **主位两库单写者**：`知识库/kb.db`、`批改产线/grading.db` 同一时刻只许一个写者。
   动主位库前先到 [记录/开发注册.md](../../../记录/开发注册.md) **登记写窗口**，用完释放；
   自己 session 里也要遵守 **「先 commit + close 再起渲染子进程」**——脚本自持写连接时
   子进程写 skill_log 会被锁死（窗G 实撞）。试验一律用副本库沙盘。
2. **闸不放宽**：块流闸／考点叶子闸／满分守恒闸／题号连号／**泄答案闸**——被拦就换题或改数据，
   **绝不改闸的判据去迁就一次出件**。泄答案闸拦下的题：把 qid 加进配方 `exclude_qids` 重跑
   `draft_paper`，不要手改库里的 paper_item（窗G 手工换题的教训）。
3. **`render-pack --out` 必须相对 v2 根**（老货架 717 行绝对路径全断）；出件目录同样相对根。
4. **组卷按 artifact 名幂等**：先查后建，命中就复用旧壳重排——`paper_run.py` 已内建，
   别自己写「直接新建」的分支（首跑失败留下 6 行孤儿 artifact 就是这么来的）。
5. **subagent 模型口径**：缺省 **opus**；简单活（检索/格式化/搬运/清点/dump）走 **sonnet**；
   🔴 **fable 仅限主循环，subagent 一律禁用**——派工显式传 model，别靠继承。
6. **发布动作永远用户手机人工**（自动化发布=封号红线）。agent 只出件、只备料、只挂账。
7. 每段落 `skill_log`：paper_tool / ingest_flow 自动落；里程碑补
   `python 工具箱/库/log_skill.py 出卷流水线 <动作> <成功|失败> "<要点>"`。

## 0. 开工前

- 问清三件：**出哪几类卷**（单元一/单元二/综合…）、**几套**（不说=出到池干）、**题源范围**
  （哪些单元/哪个版本使用级）；
- `python 工具箱/库/inject_criteria.py 出题 渲染` 注入现行判据；
- 盘一次池底，先知道能出几套：
  ```powershell
  python 工具箱/组卷/draft_paper.py --recipe 工具箱/组卷/配方/浙教U1.json --db 知识库/kb.db `
    --out-plan 试验场/<战役>/试盘.json      # 只出方案不写库，随便试
  ```

## 1. 配方（`工具箱/组卷/配方/`，契约 `paper-recipe/v1`）

现成三件：`浙教U1.json`（第1章单元卷·卷7款 100分/60min）、`浙教U2.json`（第2章·卷8款 120分/100min）、
`浙教MIX.json`（全章综合·卷8结构+温和难度+两单元对半）。
版式档案：`复刻五卷-版式旋钮.json`、`复刻卷3-组卷spec样例.json`（exam_paper 全旋钮实例）。

一份配方 = **选题配方 + 版式配方**，关键字段：

| 字段 | 是什么 |
|---|---|
| `units` / `pool.unit_kp_prefix` | 卷覆盖哪几个单元；单元 → kp_id 前缀 |
| `pool.tier_order` / `tier_exclude` | 版本使用级：一级优先、二级补；**三级绝不取** |
| `sections[].mix` | 难度配比 `[["送分",1],["巩固",3],["中档",3],["压轴",1]]` |
| `sections[].score` | 每题同分（数）或逐题分值（数组，长度必须等于该节题数） |
| `kp_cap` | 同主考点每卷上限 `[2,4]`（先 2，取不到放宽 4） |
| `降档阶梯` | 格干涸就近替补的下一档；每格最多试 3 档 |
| `exclude_qids` | 常驻排除清单（泄答案闸拦下的题写这里） |
| `layout` | exam_paper 卷头旋钮：副标题/满分/时长/评分表/密封线/head_note |

🔴 **新建配方=照抄一份改**，改完必过 `draft_paper` 的配方闸：满分守恒（逐题分合计==full_score）
与「分值数组长度==题数」两条不过直接拒收。**从参考卷提配方**的口径：数它的题型槽×题数×分值×难度分布。

## 2. 选题（`工具箱/组卷/draft_paper.py`，只读库）

```powershell
python 工具箱/组卷/draft_paper.py `
  --recipe 工具箱/组卷/配方/浙教U1.json --recipe 工具箱/组卷/配方/浙教U2.json `
  --recipe 工具箱/组卷/配方/浙教MIX.json --db 知识库/kb.db `
  --out-plan 试验场/<战役>/方案.json --out-md 产物/验收/<战役>/命题明细.md [--max-sets N]
```
- **多配方=轮转出卷**（U1→U2→MIX→U1…）直到全部停产；**五维取题**=单元×题型槽×难度×考点上限×使用级；
- **全局互不重题**（跨套），某套中途干涸**整套回滚**（占用不留残渣）；
- **确定性**：池按（使用级, qid）全序排定，无随机数——同库同配方重跑逐题复现；
- **格干涸如实停产**：打印「哪个槽×哪个难度干了」，**不硬凑**。想多出套数只有三条路：
  ①补库（录题/举一反三造题）②调配方（降压轴数量）③放宽 `kp_cap`——**不许改闸**。
- 产出：方案 JSON（`paper-plan/v1`，含逐套 layout，`paper_run` 直接吃）+ 命题明细 md
  （逐题 单元/考点/难度/使用级/来源 + 每套替补清单 + 替补落位到题号）。

## 3. 补答案（缺答案的题必须先解完再出件）

方案 JSON 的 `need_answers` 就是缺答清单。**答案卷出现「待补答案」= 出件失败**，不许交货。

### 3.1 出物料（sonnet 级活）
```powershell
python 工具箱/回流/answer_batch.py --db 知识库/kb.db dump `
  --plan 试验场/<战役>/方案.json --out-dir 试验场/<战役>/解题物料 --batches 8
```
每批一个 `批N.json`（题面 blocks 原样 + 题型 + 难度 + 落在哪几套第几题）。
🔴 **含 figure 块的题会被点名**——解题 agent 看不见图，图题走人裁或图题专线，别蒙着解。

### 3.2 双盲 + 裁判（每批派两个互不通气的 agent，opus）

**规则**：解题员与核对员**互不通气、各自独立解**；两份归一比对；**不一致或任一方低置信 → 送裁判员**；
裁判员**强制 python 实算**（sympy/分数精确算，不许口算）。定案项必须带 `verified`。

<details><summary>解题员提示词模板（model=opus）</summary>

```
你是解题员。读 <物料路径>（answer-material/v1，items[] 每项含 id/qtype/difficulty/blocks）。
逐题独立解，不要参考任何其他人的答案（本批另有一名核对员在独立解同一批，互不通气）。
要求：
① 每题给「最终答案」——就是要写进答案卷的那一句/那个值（多空填空按空分行，解答题给最终结论）；
② 给解题步骤（数组，每行一步，md+$LaTeX$，行内公式用 $…$，绝不把中文写进 LaTeX）；
③ 🔴 能用 python 实算的一律实算（fractions.Fraction / sympy），把实算结论写进 method；
   实算过的置 verified=true，纯推理未实算的 verified=false 并如实降低 confidence；
④ 拿不准就标低置信（confidence<90）+ note 写清疑点，绝不猜一个交上来。
输出 JSON：{"confirmed":[{"id":"q…","final":"…","steps":["…"],"confidence":95,
  "verified":true,"method":"…","note":""}]}，写到 <输出路径>。不要改题面，不要动库。
```
</details>

<details><summary>核对员提示词模板（model=opus，与解题员同时派、不给对方结果）</summary>

```
你是核对员。读 <物料路径>，逐题**独立重解一遍**（不要看解题员的结果，本轮就是双盲）。
输出格式与解题员相同（JSON，confirmed[]）。同样要求：能实算的实算、拿不准标低置信写疑点。
```
</details>

<details><summary>裁判员提示词模板（model=opus，只吃分歧题）</summary>

```
你是裁判员。以下题目解题员与核对员结论不一致，或有一方低置信：<分歧清单：id + 两方 final + 各自理由>。
🔴 强制 python 实算：对每题写一段可运行的 python（fractions/sympy 精确算，不要浮点凑），
   跑出来的结果才是定案依据；口算/眼看一律不作数。
逐题给：定案 final、定稿 steps、confidence、verified=true、method（写清实算路径）、
note（写清两方为何分歧、错在哪一步）。若实算发现**题面本身有毛病**（无解/多解/条件缺失），
不要硬解——标 confidence<90 + note 写明，送人审换题。
输出 JSON：{"refereed":[…]}，写到 <输出路径>。
```
</details>

汇总壳（`answer_batch pack` 三种都吃）：
`{"result":{"batches":[{"confirmed":[…],"refereed":[…]}]}}` / `{"batches":[…]}` / `{"items":[…]}`。

### 3.3 打包对账 + 回写
```powershell
python 工具箱/回流/answer_batch.py --db 知识库/kb.db pack `
  --result 试验场/<战役>/定案.json --material "试验场/<战役>/解题物料/批*.json" `
  --out 试验场/<战役>/答案包.json
# 缺一题都会报「没交答案的题」并返回非 0 —— 补齐再往下走，不许带缺口出件
python 工具箱/回流/ingest_flow.py --db 知识库/kb.db patch-check 试验场/<战役>/答案包.json   # 干跑
python 工具箱/回流/ingest_flow.py --db 知识库/kb.db patch-answer 试验场/<战役>/答案包.json  # 🔴 写库：先登记写窗口
python 工具箱/回流/answer_batch.py --db 知识库/kb.db check --plan 试验场/<战役>/方案.json   # 覆盖率复查
```
- `verified` 不为真的一律被压进低置信档（<90），`patch-answer` 会点名待人审——**照单人审，别放行**；
- 答案只有 `answer_blocks` 一份（第二载体字段会被闸拒收）；解析进 `analysis_blocks`。

## 4. 出件（`工具箱/组卷/paper_run.py`）

```powershell
python 工具箱/组卷/paper_run.py --plan 试验场/<战役>/方案.json --db 知识库/kb.db `
  --pack-dir 试验场/<战役>/packs --out-root 产物/验收/<战役> [--only U1·1] [--limit 2] [--timeout 900]
```
一套一条链：**spec → assemble（按名幂等）→ render-pack（相对根）→ 双 PDF + 全页目检 PNG → 机器验页**。
机器验页四条：题目卷/答案卷各自 **页数≥1｜题号 1..N 连号｜零「待补答案」｜目检图张数==页数**。
- 🔴 库连接**开→查→立刻关**，绝不跨子进程持连接；
- 🔴 超时是**常量**（`--timeout`），失败/超时**重试一次**——绝不用「截止减现在」算剩余（负超时炸批的血案）；
- Chrome 三坑（临时 profile／`--no-proxy-server`／出完验文件存在）由 `render_paper.py` 内部保证，
  `paper_run` 出件后再目验一次文件真的在盘。
- **出件后必人工 Read 目检**：`_源/_chk_question_p*.png` 逐页看（版面破没破、公式渲没渲出来、
  图题在不在位、跨页题有没有顶格起排）——机器验页只管数得出来的，版面好不好看只有眼睛知道。

## 5. 收尾（明细 + 挂账）

1. 命题明细 md（§2 已随选题产出）落 `产物/验收/<战役>/命题明细.md`——逐题带 单元/考点/难度/使用级/来源，
   逐套带替补清单；**替补是如实记账不是瑕疵**，别删。
2. 挂账走「资料挂账」skill：`artifact_tool.py files/status/note` 补真文件、改「已交付」、回填宣发字段。
3. 卷类新版式定稿了才 `template-add` 登记（停用不删，发出去的卷还是老版式）。
4. 记账进 `记录/迁移记录.md`：出了几套、用题多少、哪格干涸停产、替补几处、闸拦了什么怎么处理的。

## 6. 撞墙决策表（别自己发明新路）

| 现象 | 正解 | ❌ 禁 |
|---|---|---|
| 某格干涸停产 | 补库 / 调配方 / 放宽 kp_cap，重跑 draft_paper | 硬凑一题填格、改闸 |
| 泄答案闸拦下某题 | 先核是不是真泄漏（渲染注入的答案元素混进题目卷）——真泄漏=修渲染再重出；题面固有「解：/答：」**已白名单化不再误拦**（2026-08-20 段D 落地：闸只认渲染器注入的 `.ln ind`/`ansv`/着色/科学 `class="a"` 等令牌，不拦题面 md 原文）；仍被拦=qid 进配方 `exclude_qids` 重跑 | 手改 paper_item 换题、放宽闸 |
| 答案卷出现「待补答案」 | 回 §3 把缺答题解完再出件 | 交货、或手填一句糊弄 |
| 题号缺号/页数不对 | 看 `_源/` 的 HTML 与目检图定位，多半是 layout 节名对不上或分值数组长度不符 | 改验页脚本的判据 |
| 组卷报「题在本册已出现过」 | 方案里同套重题——重跑 draft_paper（互不重题是它保证的） | 手删一行 paper_item |
| assemble 报 take 取不足 | 本 skill 不用 take（qids 显式给），报这个说明 spec 拼错了 | 降 limit 蒙混 |
