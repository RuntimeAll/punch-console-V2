# KG 弹性机制设计——本体与教材分离（2026-08-21 · 策略正本，未开工）

> 用户命题：现在 1000 题还能重构，后面几万题；教材版本会变，题库要不断更新，
> 「最新的好用的永远有人要」——维护性就是产品护城河。一旦铺开回不了头，现在从更高角度定架构。
> 本文承接 [KG加层策略.md](KG加层策略.md)（题型层方案并入本案作段0）。

## 一、问题的本质：一棵树背了两种命

现在的 kp 树把两种**变化速率完全不同**的东西焊在一起了：

| | 变化速率 | 例 |
|---|---|---|
| **教材目录**（版本→年级学期→单元→小节） | 教材一改版就变：章节重排、合并、拆分、跨册搬家 | 实数在浙教是七上第3章，人教在七下第8章 |
| **知识本体**（考点、题型） | 几乎不变：「相反数」「去括号」「绝对值的几何意义」不随改版消失 | 71 片叶的名字全是版本无关的（当年 R1 体例定对了） |

更要命的是 **id 把两者焊死了**：`100001003004` = 浙教树100 → 第1单元 → 第3小节 → 第4考点，
**位置就是身份**。推演一下改版那天会发生什么：

> 浙教 2027 改版，把「实数」并进「有理数」章 → 单元号全变 → 按现在的 id 规则整棵树要重编号
> → 几万条 question_kp、solution_model 的 kp_ids_json、别名表、题型映射件**全部重挂**
> → 这就是死局。老区 2012/2024 两版并存靠的是**建两棵全量树**（500 和 100 两个根），
> 题挂哪棵全凭当时手气——这条路不能再走。

## 二、目标架构：题挂本体，目录变成可替换的视图

```
┌─ 资产层（题/册/卷/模型）────────────────┐
│   question_kp ──只挂──▶ 本体层           │   ← 几万题的家，永不重挂
├─ 本体层（考点 → 题型）──────────────────┤
│   永久 id·不编位置·版本无关              │   ← 慢变层，全系统唯一锚
├─ 教材视图层（每版本一棵目录树）──────────┤
│   浙教2024树 ─映射─▶ 考点                │   ← 快变层，可整棵新增/退役
│   人教2024树 ─映射─▶ 同一批考点          │
└─────────────────────────────────────────┘
```

三条铁律：

1. **题只挂本体**（考点或其下题型），永远不挂目录节点——改版与题库零耦合；
2. **目录树是视图**：单元/小节节点不再"拥有"考点，只**引用**考点（映射表 M:N 带 ord）；
   一个考点可以同时被浙教树第3章和人教树第8章引用，这就是"实数跨版本跨册"的正解；
3. **改版 = 建一棵新树 + 一套映射**（天级人工，还能从旧映射 diff 起步），旧树整棵转「退役」
   留档可查，**题一道不动**。

题上已有的 `prov.版本使用级`（一级·浙教/二级·人教互通/三级）继续管"这道题适合哪版用户"，
与本体挂载正交——本体答"考什么"，使用级答"给谁用"。

## 三、弹性机制五件（撑住"不断扩张"的具体机构）

### 机制1　id 永久化：身份与位置解耦
- 存量 71 考点 id **原样冻结**（`100001003004` 从此只是无语义字符串，全链路引用不动）；
- **新节点 id 不再编码位置**（kp+日期+hex，同 question id 风格），位置只活在映射表/parent_id+ord 里；
- 🔴 配套纪律：**全库禁止 id 前缀聚合**。实测现状只有一处在用
  （工具箱/组卷/draft_paper.py:123 单元维度 `kp_id LIKE 前缀%`），改成"单元→映射表取考点集"
  即可——这是整个 id 解耦唯一的代码代价，半天。

### 机制2　树按数据压力生长（承接加层策略的「就近可挂」）
- 叶子闸从"必须无子节点"改为"**必须是所在枝末端**"：考点可后长题型子层，长哪片沉哪片；
- 树的深度不是设计出来的，是**题量压出来的**——这就是"弹性拓展"的日常形态。

### 机制3　生命周期三原语：拆叶 / 并叶 / 挪枝
弹性 = 改得起。每个动作做成 kg_tool 子命令，不许手 SQL：
- **拆**：`绝对值的概念(138题)` → 六个题型子节点，题按映射下沉，沉不动的留父层带标记；
- **并**：小叶合并，被并叶转退役、note 记 successor id，旧 id 查询自动转发；
- **挪**：考点换属（只动映射/父指针，id 不变，引用零断）；
- 每次动作自动落：别名行（旧名永远可查）+ skill_log + 迁移记录一行。**退役不删**——这是
  "两年后的资料还能考古"的底座。

### 机制4　容量守恒闸：让维护变成例行公事而不是抢救
- **过厚告警**：叶挂题 >150 → 自动出"拆叶工单"（数据压力驱动机制2）；
- **空叶巡检**：0 题叶季度报表（老区血案：2781 叶实际用到 322 片，88% 白建——宁按需生长不预铺）；
- **低置信复审**：anchor_json.confidence 低于阈值的挂载进人审队列（列已建成，今天就有）。

### 机制5　挂载产线三级：几万题怎么挂得动
人工逐题挂载在万级题量下必死，产线化为三级漏斗：
1. **来源结构映射**（零成本）：讲义题型→考点的映射件已锚定 103 型，同源题直接机器挂；
2. **语意候选**（低成本）：检索三层的向量已全量建好（1090/1090），新题算最近考点给 top3 候选；
3. **人审兜底**（保底）：前两级置信不足的进队列，人只处理灰区。
主次挂载（is_primary）**已建成**，多考点题不必硬塞一个格。

### 机制6　考点层自己也进向量：建叶闸 + 聚簇巡检（2026-08-21 用户点名补入）
- 每个本体节点带**两路向量**：①文本向量——🔴 **必须带全路径**（2026-08-21 用户定准入标准：
  年级-学期-章/单元-小节-节点名[+desc] 拼一串再 embed）——路径给语意定位，跨年级同名
  （四下/八下「平均数」）天然分开，同枝近义（「绝对值化简」vs「化简绝对值」）天然聚拢；
  ②挂载题的**质心向量**（题多了以后更准——一个考点"实际在考什么"由挂在它身上的题定义，
  不由名字定义）；
- **建叶前置闸**：录题中发现要建新考点 → 先拿新名+代表题对现有节点近邻查 →
  top1 相似度超阈值就拦下：「已有近似考点 X（附路径），挂它还是真建新的？」，拿不准低置信进人审。
  防的就是老区 236 组重名的病——考点野蛮增殖不是录题人的错，是没这道闸；
- **聚簇巡检**（季度/按需）：全体考点质心跑近邻对报告——「这两片叶的题分布高度重叠，建议并叶」
  → 出工单喂给机制3 的并叶原语；升降维同理（一片题型厚得像考点了→升维工单）；
- 🔴 **准入判词（用户原话口径）**：「确认没有近似值非常高的才能新增，不然都挂一起」——
  建叶闸即此标准的机器化；题目侧同理：录题的**精确排重（match_key）已是硬闸**，
  **语意近似前查**待进闸——但对题只做**提示不硬拒**（近似题可能正是要的变体，
  确认是变体就带血缘入库，确认是重题就拒）；
- 定位铁律不变：**向量只提名，闸判决，账本落地**——聚簇结果永远是工单，绝不自动改树。

## 四、量级账（如实）

- **存储与查询**：SQLite 单文件到十万题量级无压力（树遍历用 CTE 替代前缀 LIKE，需在
  question_kp.kp_id 上补索引——顺手的事）；瓶颈从来不在库，在人工挂载，机制5 就是答案；
- **本体规模预估**：初中数学全段约 500 考点 + 1000~1500 题型，封顶也就几千节点——
  本体永远是小头，**大头是题，而题不动就是这个设计的全部意义**；
- **改版成本**：新版本 ≈ 目录树 100~200 节点录入 + 映射 diff 复核 ≈ 1~2 天/册，
  且是**卖点成本**（"跟最新教材"正是别人买单的原因），不是技术债。

## 五、改版剧本演练（用假想浙教 2027 验证设计）

1. 建新树根「浙教2027·七上」，从 2024 树复制映射作底稿；
2. 按新教材目录调整：章节重排=改 ord，章合并=映射改指向，新增考点=本体加节点（新式 id）；
3. 被新版删掉的考点：**本体不删**（旧版题还挂着），只是 2027 树不再引用它;
4. 2024 树转退役留档；出卷配方里的"单元"维度从此按 2027 树解析；
5. **question_kp 改动行数：0。** —— 这一条是整个设计的验收判据。

## 六、迁移路线（数据小是唯一的窗口，全程沙盘先行）

> 🔴 存量处理口径（2026-08-21 用户令）：**只精处理试卷线，批量线剔除重录**。
> 实账：试卷线 = 161 题（卷1~5 复刻＋卷7/8，人工资产=双盲答案/裁图/工单审）——**保全零动**；
> 其余 929 题全是确定性管线的产物（讲义抽取 641 + 老册吃库 228 + DSL 生成 60）——
> **不逐题迁移，管线对着新树重跑一遍**，讲义题凭题型映射直接落到题型节点上。
> ⚠️ 实现走 match_key 幂等重挂（命中即更新挂载、**id 不变**），不做硬删重插——
> 已交付的浙教出卷 10 套和发布包引用着这批 qid，硬删就断血缘；效果与重录等同，人审归零。

| 段 | 内容 | 工期 |
|---|---|---|
| 段0 | DDL+叶子闸改「就近可挂」，沙盘+正反例 | 0.5 天 |
| 段1 | 题型层铺枝：映射件 103 锚定型 + 59 细分型归位成节点 + 一本通 8 专项节名，约 150 节点；映射件漏键顺手修 | 0.5 天 |
| 段2 | 建映射表，读路径切换（draft_paper 单元维度 / console 树 API / coverage 对账）；存量 71 考点落第一棵树 | 1 天 |
| 段3 | 批量线重挂：讲义 641 管线重跑落题型、DSL 60 重生成、老册 228 重吃（无题型标注，留考点层）；每管线抽 20 题目检 | 0.5 天 |
| 段4 | 新 id 规则 + 拆/并/挪三原语 + 容量三闸 + 套件回归 | 0.5 天 |
| **合计** | | **~3 天** |

比旧案（3.5 天 + 334 题人审）省的不是半天工期，是**人审整段归零**——待归位的 59 个细分题型
在新架构里本来就该是题型节点（对齐-003 的结论），归位即建节点，不再是"人审债"。
对照不做的代价：几万题之后再拆 = 周级停摆 + 全量挂载人审雪崩。**窗口就是现在。**

### 🔴 双线执行口径（2026-08-21 用户令：不沉浸式开发，边开发边产出）

- **日常产出线（主位，优先）**：立刻用现行 KG 出后面章节的专项打卡——产出**不等重构**，
  按考点+难度选题今天就能出件；
- **开发常驻线（worktree 沙盘，后台）**：重构砍成最小件先行——段0+段1（闸改+题型枝，1 天）
  直接服务产出线（出册按题型取题）；段2/段4（映射表/id 规则/三原语）拆成 0.5 天粒度
  穿插在产出间隙做；**段3 历史重挂无限期后置**——就近可挂保证旧挂载永远合法，
  什么时候闲了什么时候清，不清也不错；
- 两线交汇只在主位写窗口（产出线选题挂账/开发线 DDL 落库），照开发注册排队，互不挡路。

## 七、明确不做的（防过度设计，各有老区血案）

- ❌ 不预铺全初中/全学科大树——老区 88% 空叶教训，树按需生长；
- ❌ 不上图数据库/本体语言（OWL 之类）——SQLite 两张表 + CTE 到十万级够用，工具链全保留；
- ❌ 不给考点编"课标编码"对齐国标——没有消费方，是装饰性工程；
- ❌ 不动 71 片叶的现名现 id——存量引用（题/别名/模型/映射件）全部零断链。
