## §0 一句话结论

**老区的「一道题」不是一个结构，是四套并存的结构 + 三条互不通气的入库管道。**

| 层 | 谁在用 | 「一道题」长什么样 | 事实源 |
|---|---|---|---|
| **L0 产线出料** | 打卡/专项出卷器（`gen_打卡.py`） | `punch-ingest/v1` 题级 10 字段（`day/section/seq/stem/answer/考点/题型/难度/来源/实算`），**无解析、无题级图、无校验器** | `codeplace-O\punch-console\web\scripts\import-all.ts:859-870` |
| **L1 知识工厂** | `codeplace-AI\knowledge-factory` | `kb-ingest/v1` 题级 12 字段 + **十道硬闸** + zod schema 文件，是 L0 的严格超集 | `contracts\kb-ingest-v1.md`、`src\core\ingest-schema.ts` |
| **L2 系统题库（真·备课帮）** | book-server + book-ui + teacher-mcp | `IngestItem`（MCP 26 字段）→ `IngestQuestionBo`（BE 18 字段）→ `biz_question` + 8 张附属表；题面**双写** `stem_text`（纯文本）+ `block_json`（rows/cells 结构） | `codeplace-O\teacher-mcp\src\teacher_mcp\tools\data_qbank.py:114-142`、`codeplace-O\book-server\...\bo\IngestQuestionBo.java` |
| **L3 录书线** | `录书工作区\小学数学管线` | 走 L2 的 HTTP 口，但自带 `born_correct` 整形带账 + `preflight_lint` 静态闸；题号编进 `externalKey` | `ingest_unit_rb.py:191,225-262` |

**拼起来一道题的完整描述 = 5 块**：
① 题面三件（stem / answer / analysis，两种表示：纯文本 + 结构块流）
② 归属（考点 kp 数组 + 主考点恰一 + 载体位置：卷位 / 书节点 / 打卡天节 / 专项区块）
③ 元信息（题型、难度、来源四要素、分值——🔴 **分值不在题上，在卷位上**）
④ 判据结果（match_key、实算三态、solution_grade、置信度、审核态）
⑤ 血缘（母题、变式档位、生成器+seed+params、解题模型链、导入批次号）

🔴 **老区最贵的一条契约教训**（punch → kb 的态度差，`contracts\kb-ingest-v1.md:17-19`）：
> punch 那边「认不出的契约 `console.log` 跳过、stem 只 `trim()`、实算信产线自报、查重只算 hash 不拦」；
> kb 这边「坏料一律红灯 + 人话 + 怎么改，一个字都不静默」。

**闸⑧ 的两判据分工**（`ingest-calc.gate.ts` 头注释，v2 最该抄的一段）：
- ① `calc_verify` 验最终答案 → `CALC_MISMATCH`；
- ② `line_verify` 验过程每一行 → `CALC_LINE_MISMATCH`，补的正是①**结构性验不出**的「答案对、过程错」（LLM 写解析去括号漏变号、末行又锚回正确答案）；
- 送算范围：`qtype='计算'` **或** `looksLikePureExpression(stem)`（无中文 + 有数字 + 有运算符）；逐行校**窄**到 `qtype='计算' 且有 analysis`；
- ⚠️ 诚实边界（原文自标）：`line_verify` **只判数值链**，含未知量的变形链（解方程/字母化简）一律 `no_checkable_lines` 记账放行——「假红拦下真题的代价比漏判一条大」。

**判档口径 `question.solution_grade`**（`contracts\kb-ingest-v1.md:208-214`）：

| 档 | 条件 | 语义 |
|---|---|---|
| `calc_verified` | 闸⑧实算 verified | ⚠️ 判档**只看最终答案**；过程对不对由 `CALC_LINE_MISMATCH` 拦，不进判档 |
| `analysis_only` | 有 analysis **或** 有 answer | `qtype='计算'` 却算不动又没解析 ⇒ 落这档 + 账上 warn |
| `no_solution` | 两样都没 | 🔴 排除出出题检索；契约层已拦，闸⑨是防御 |

**闸的分工纪律**（`gates\ingest-context.ts:4-20`，v2 直接照搬）：
> **管道做变换，闸做判定。** 每个闸文件导出两样：① 纯函数（确定性、无 IO、可脱库单测）；② `Gate` 对象（读 `derived`，判红绿，把结论写回 `derived`）。
> 变换塞进闸里 ⇒ 闸有顺序耦合、单测一道闸得先跑前四道。
> `derived` 是**可变**的：闸的产出不只是红绿，还有「该怎么落」（kp 绑定 / 判档 / 配图计划）。

`ItemDerived` 16 个中间物（`ingest-context.ts:57-89`）：`stemStripped / stemClean（=真正落库的 stem）/ stripped[] / sampled[] / notes[] / matchKey / stemPlainSeg / answerSeg / analysisSeg / calc / lineVerify / kps[] / solutionGrade / figures[] / reviewRequired`。

**第三形态·群卷题单**（`convert-punch.ts:229-237`）：`no / q / ans / kp / diag / kp_group / anchor`。
🔴 `anchor` 有三种对不上词表的形态（005-C 实测）：歧义（`sign` 同时是两个考点别名）、不是考点名（整条 anchor 是 LaTeX）、为空（只有 `kp_group`）。

**转换器纪律**（`convert-punch.ts` + `contracts\kb-ingest-v1.md:145-148`，v2 该抄）：
> 转换层只做「搬运 + 有据可查的折算」：题面一个字不改，认不出的字段**如实进报告（不静默丢）**，每一次归一都在 `normalizations` 里留一行。
> 例：`口算 → 计算` 这次折算**有后果**（`计算` 是唯一触发实算闸的题型，折过去等于替产线宣称「机器算得出来」），所以折了必记账；表里没有的题型**一律不猜**，留空 + warning（`convert-punch.ts:239-246`）。

**两个 CLI 入口，别混**（`scripts\kb-ingest.mts:6-10`）：
- `pnpm kb:submit <产线出料>` —— 吃 punch 三形态，先 `convertPunchIngest` 再投；
- `pnpm kb:ingest <载荷.json>` —— 吃**已经是 kb-ingest/v1** 的载荷，直喂 `runIngestBatch`；
- 两者**默认 dry-run**（跑完全套闸、库与磁盘零变化），`--real` 才真写；退出码 0=无红灯 / 1=有题被拒 / 2=载荷读不了。

### 3.2 `resolve_kg` / `resolveKp` 怎么把名字解析成叶子

## §5 排重 match_key 算法与查重口径

### 5.1 `match_key` 算法（kb 口径，v2 直接用）

`src\core\gates\ingest-dedup.gate.ts:89-102`。`matchKeyOf(stem) = sha256Hex(normalizeStem(stem))`。

`normalizeStem` 四步，**顺序钉死**：

| 步 | 做什么 | 🔴 为什么这么写（每条都有血） |
|---|---|---|
| ① 剥 HTML 标签 + 解实体 | `RE_TAG = /<\/?[a-zA-Z][^<>]*>/g` → `" "`；再按 `实体表` 解 `&nbsp; &lt; &gt; &quot; &#39; &amp;` | 🔴 **只认标签形状**：`<` 或 `</` 后必须紧跟 ASCII 字母，属性区不许再出现 `<`。旧版是宽松的 `<[^>]*>`，在真库 60 行里**实测 2 行中招**：`有理数 a < 0，b < 0，c > 0` → `有理数a0且…`（`0，b < 0，c` 整段被吃）；`（用 < 或 > 或 = 号填空）` → `(用或=号填空)`。后果 = **查重键失真**，两道只在被吃段上有区别的题撞成同一道（假 DUPLICATE）。<br>🔴 **先剥标签后解实体**：反过来 `&lt;span&gt;`（本该当正文读）会先还原成 `<span>` 再被剥掉——凭空吃掉正文。<br>🔴 `&amp;` 必须排最后（先解它，`&amp;lt;` → `&lt;` → `<` 二次解码） |
| ② LaTeX 归一 | 去 `\left \right \, \; \! \quad \qquad \displaystyle`；去定界 `$$ $ \( \) \[ \]` | `$x^2$` 与 `\(x^2\)` 是同一道题的两种写法 |
| ③ `NFKC` | 全角→半角、`ｘ`→`x`、`²`→`2` | 顺带把全角标点折成半角，④ 才好统一处理 |
| ④ 去空白 + 去**句读**标点 | `RE_PUNCT_NOISE = /[\s　，。、；：！？,;:!?"'`""''《》〈〉«»…—～~·・､｡]/g` | 🔴 **不是「去所有标点」**：ASCII `-` 在 Unicode 里是 Pd、`( )` 是 Ps/Pe，用 `\p{P}` 一刀切会把 `3-5` 削成 `35`，于是 `3-5` 和 `35` 撞成同一道题。**运算符与括号一律保留** |

**换口径 = 全库 match_key 作废重算**，不能只改代码（`:59-62`）。003-E5 换口径时连带做了两件事：撞键预检（新口径下 60 行两两不撞——预检撞 = 真重复题，**要停手报告不是硬写**）+ 一次性重算脚本 `scripts\recompute-matchkey-20260813.ts`（审计 `tool='matchkey_recompute_20260813'`，实际改动 2 行）。

**算键前必须先做同款变换**（`dedup.ts:133-137`）：
```ts
matchKeyOfStem(stem) = matchKeyOf(cleanStemPrefix(stripLeadInstruction(stem).text.trim()).text)
```
🔴 「先剥指令词、再清前缀，最后算键。少剥一层，算出来的键就和入库时的键不是一个东西——断言会绿、入库照样撞，**那比没有断言更糟（它给了一个假的放心）**」（`dedup.ts:23-25`）。

**对比 punch 的 `hash_L1`** = `sha1(NFKC(stem) 去所有空白)`——kb 口径是它的超集（多剥 HTML + LaTeX 归一），且**真的拦**（punch 只算不拦、无唯一索引）。

**册内 `verify()` 全部硬断言清单**（`qbank.py:484-585`，v2 出题线该照搬）：

## §6 展示与导出契约 + 内容纪律

### 6.1 前端渲染吃什么（L2 三端统一格式）

**`block_json` = 唯一渲染源**，`stem_text` 只是纯文本影子（全文检索 + 去重 hash）。

结构（`preflight_lint.py:8` + `apply_lib.py:51-67 schema_ok`）：
```jsonc
{ "v": 1, "rows": [ { "cells": [
    { "type":"text",   "md": "…markdown（可含 $LaTeX$、GFM 表、![](url)）" },
    { "type":"image",  "url": "…", "width": 30, "align": "left" },
    { "type":"option", "label": "A", "content": [ {type:'text'|'image', …} ] }
] } ] }
```
- **只有三种 cell 型**：`text`（必有 `md`）/ `image`（必有 `url`）/ `option`（必有 `label` + `content`），其余型 = schema FAIL；
- 一题三份：`block_json` / `answer_block_json` / `analyze_block_json`（`get_question` 返回，`shared.py:439-441`）；
- 🔴 **选项内容在 `block_json` 里，没有独立 `options` 字段**（`shared.py:442`）；
- ⚠️ 但录书线实际只产 `text` + `image` 两型：`build_block_json`（`ingest_unit_rb.py:111-116`）**一个 option 块都不产、一个 table 块都不产**（坑清单 §0.2-③：一下 52 题 / 四下 30 题 / 二上 23 题全靠事后 F1 战役返修）。

**`format_question` 的规范化边界**（`codeplace-C\toolkit\src\agents\qtype_format.py:1-22`，SSOT = `book-ui\src\views\variant\normalize.ts`，**两轨必须一字不差**）：
> 规范是**纯排版（cosmetic）**——只动换行/下划线/补括号/选项分行，**绝不改数学语义、绝不动 `$...$` 内的 LaTeX、不重排选项、不改字**。解析不出 → **原样返回，绝不报错**（降级 G5）。**幂等**：已规范的文本再跑一次结果不变。
三类处理：① 选择题每选项独立成行（存储一行一项，2×2 是 FE 渲染层的事）；② 填空占位统一成 `BLANK="____"`（4 个半角）；③ 判断题尾无括号则补 `（  ）`。
选项 A2 SSOT `dedup_cap_reorder_choice`：按 label 去重（保留首次）→ 封顶 8 → 按 A/B/C… **连续重排**（**绝不产出 label=`?`**）。

### 6.2 导出吃什么

**① 专项 compose→bind→export 链**（`teacher-mcp\tools\special.py`）：
- `compose_special(title, picks[{questionId|nodeId, secHint, overrideJson}], grade, subject_id)` → 建 `book_type='special'`（复用 `biz_shelf_*` 三表），结构 = **区块(sec) → 难度档(tier) → 题**；跨书 = picks 可来自不同源书，**专项只引用题库题 id，不动源书与题库**；

**② 打卡书（prod）**：`upsert_punch_day(book_id, day, goals[], modules[])`（`punch.py:58-143`），整天覆盖幂等。三类 module：
- 计算模块 `{type:'oral'|'vertical'|'stepwise', title, items:[{q,a}]}` —— 题**不在题库**，内容随书存 `content_json`；`q`/`a` 必**成对给全**（答案缺失 = 解析卷开天窗）；

**③ 本地打卡册 punchkit**（`.claude\skills\每日打卡\templates\punchkit\`）——**两层结构**：

### 7.1 前缀清洗的 11 条正则（kb 闸⑤ = 老区三份正本的合并移植）

🔴🔴 **`STEM_PREFIX` 的 `(?!\d)` 负向前瞻是必须的**（`ingest-prefix.gate.ts:82-89`，v2 照抄别省）：
> 原文是 `^\s*\d{1,3}[．.、]\s*`，在 `preflight_lint` 里只是**软告警**（不在 HARD 集合，人看一眼再说）。搬到闸里是**要真剥**的——而 `1.5 米的绳子…` 会被原正则剥成 `5 米的绳子…`，**题目当场变错**。加一个前瞻，代价是 `1.5` 这种真题号（不存在）剥不掉，换来的是小数题面不会被咬。

**剥离算法**（`cleanStemPrefix`，`:120-142`）：
- 规则表顺序 = **先具体后宽泛**：`BRACKET → SCENE → COLUMN → SHUA → PTYPE → MOTHER → PITFALL → THOUGHT → LABEL → STAR → STEM_PREFIX`；
- **命中一条就重头再来**（`break` 内层，对齐 `clean_stems` 的 `continue` 语义），最多迭代 **8 轮**（防多层叠加，也防死循环；`clean_stems_v2` 是 6 轮）；
- 🔴 **剥完不能是空的**：整条题面就是一个标签时 `continue`（宁可留着让占位闸去红，也不要静默产出一道空题）；

- 逐条留痕：`stripped: string[]`（原样片段），**页页有账**。

`parse_block(num, block, section_type_)` 的抽离顺序（`:115-176`）：

3. **抽来源**：`src.split("【来源】",1)[1]`，再 `re.sub(r"第\s*\d+\s*题\s*(?:\d+分)?\s*$", "", raw_src)` 去掉尾部「第N题 X分」；
4. **填空空白 → 下划线**：`BLANK.sub("______", …)`（🔴 **在 strip 前替**，免被 strip 吃掉尾部空白）；
5. **状态机分段**（`:132-158`，修多小问截断）：题面结构 = `[主干] (1)…【答案】…【解析】…(2)…【答案】…【解析】…`；遇【答案】/【解析】切到对应缓冲，遇新小问标记 `(n)` **切回题干** ⇒ 不再在首个【答案】处截断、(2)(3) 不丢；遇【标注】 `break`；
6. **抽选项**：`OPT_LINE` 或行内多标记 → `split_inline_options`；
7. **删来源行**：`while stem_lines and SRC_LINE.search(stem_lines[0]): stem_lines.pop(0)` —— 🔴 `SRC_LINE` **不锚定行尾**，抓「…A卷第10题4分」这类多重来源第二行；靠「含**第N题**标记」这个来源引用独有的特征避免误伤真题干（`:21-23`）；
