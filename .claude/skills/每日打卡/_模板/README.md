# 每日打卡 · 模版库（2026-08-03 立）

> **一句话**：造新册**先来这里选模版**，不要再 fork 别人的 `gen_打卡.py`。
> 选模版 = 选一个**版面骨架** + 挂一个**学科渲染器**。

```powershell
cd D:\workplace\ai-bkb\.claude\skills\每日打卡\templates
python -m punchkit          # 看全部模版
python -m punchkit 科学      # 只看科学能用的骨架
```

## 为什么要有这个库

抽离之前：6 本册 = 6 份 `gen_打卡.py`，每份 300~500 行，其中**一大半完全相同**——
HTML 外壳、MathJax 注入、水印 base64、Chrome 出 PDF 三坑、页数断言、泄答案闸。
改一处漏五处；Chrome 那三个坑前后踩了三次，就是因为每份各抄各的。

抽离之后：

```
共用管道  punchkit/core.py         ← 六件事，只此一份
   ×
版面骨架  punchkit/layouts/<key>.py ← 学科无关：分几节 / 有没有边框 / 留白怎么分 / 一页几天
   ×
题型渲染  punchkit/renderers/<学科>.py ← 学科相关：一道题怎么变成 HTML
   ×
册子内容  <册>/_源/qbank.py + days.py ← 题库 DSL + 排班表（**留在册子里，不进库**）
```

册子的 `gen_打卡.py` 瘦成 **~60 行的配置 + 一次调用**。

## 🔴 两层拆分的理由（骨架 / 渲染器）

**「一页两张纸条」这种排法与教什么科目毫无关系**——数学能用，科学也能用。
所以骨架的 `SPEC['学科']` 默认就该是 `'通用'`；写具体学科前先问一句
「这排法换个学科真的不成立吗」。

真正分学科的是**一道题怎么渲**：
- 数学要 MathJax 行内公式，而且 🔴 **MathJax 渲出的公式不吃外层 CSS 的 font-weight/color**
  （踩过两次），答案着色只能 `\color{}` 写进 LaTeX；
- 科学多半不含公式，但要配图、选项网格，答案用普通 `<b>` 就行。

## 🔴 这个库真正解决的事：内容与版式解耦，一行换装

**同一份内容，可以出好几个版式的册子**；**一套好用的版式，可以给后面所有册子复用**。

```python
LAYOUT = 'dense_sections'    # ← 改这一行，内容一个字不用动
```

已验证的换装（2026-08-03）：

| 册 | 内容 | 原生版式 | 换装成 | 结果 |
|---|---|---|---|---|
| 五升六暑假每日一练 | 分数加减 20 题/天 | 边框分节 | **三上那套** | ✅ 双卷各 1 页 |
| 五上计算强化每日一练 | 小数计算 28 题/天 | 无框 6 节 | **三上那套** | ✅ 双卷各 1 页 |

### 🆕🔴🔴 换装的头号用途：**A/B 双号各走一套骨架**（2026-08-05 用户拍板）

> 用户原话：**「AB版需要走不同的模版了，就算是水印也不顶用」「数据源统一，走两个不同的模版出」**。

小红书两个号发同一本册子会被**判重限流**。此前靠「水印深浅 + dpi 错开」躲，
**这条已作废**——平台判重看的是**版面结构**（栏数、题号形状、留白分布、节头形式），
水印只是页脚几十个像素、dpi 只是整体缩放，**都改不动结构**。

```python
for tag, layout in [('A', 'dense_sections'), ('B', 'boxed_sections')]:
    render_book(layout=layout, days=DAYS, ...)     # ← 同一份 days，换骨架
```

🔴 **这正是本库存在的最大理由**：内容与版式解耦后，出第二套版面**零内容成本**。
选骨架时**顺手想一想「这册的 B 版配哪个骨架」**——两套差得越像两本不同的书越好
（无框大留白 ↔ 边框分节，就是一对现成的强对比）。

🔴🔴 **换骨架只解决了正文**（2026-08-10 补，用户：「两个AB线相互隔离，两者不互通，
内容同源但页面排版和结构不同」）。册子若有**封面/目录**（合刊、成书），
那两页**也必须两套版式** —— 七上第二单元合刊本踩过：正文分了骨架，
出书脚本的前页却两版共用一份 CSS（只换了输出文件名），
于是 A 号发的第 1 张（封面）与 B 号发的第 1 张（目录）是同一套设计语言，
**漏在最显眼的位置**。做法 = 出书脚本挂一张「版 → (CSS, 封面, 目录)」表，加版只加一行
（样板 = `打卡/七上第二单元打卡册/_源/_成书.py` 的 `FRONT`）。

四条闸：
1. **数据源必须同一份**（题、答案、顺序一个字不改）——改了两个号的答案对不上，客户以为买错。
2. **两套各自跑页数断言**（题目卷页数 = 天数），别只验 A。
3. **两套都要目检**——换骨架后的排版事故（题被挤断、留白塌了）契约校验拦不住。
4. 🔴 **跑 `AB隔离闸.py`**（同目录）——逐页比两版**几何指纹**，撞了就报；
   配图另查字节重复与取线重叠。**七条隔离维度靠人记一定漏，这道闸漏不了。**

## 已知的坑（入库时踩出来的，照抄省时）

1. 🔴 **多列 grid 里每题必须裹 wrapper** —— grid 按**直接子元素**分格，而
   「解方程 / 应用题」这类槽位**一道题返回多个兄弟 div**（题头 + 各解答行）。
   不裹就会把一道题拆散到几列：`dense_sections` 实测过「①的题头在左列、解答行排到右列」，
   `daily_v1` 2026-08-04 出 400 题全册时**整节解方程被打散**（①的题面在第 1 格、
   它的答案在第 4 格）。🔴 **新写骨架时默认就裹**，别等目检抓。
2. **`block` 节要用 `gap_each` 而不是 `gap`** —— 三上原版第三/四节题目自带作答位
   （综合算式横线、树状图），节末留一次就够；但应用题这类**题面各占几行**的，
   节末留一次会把两道题挤成一坨。
3. 🔴 **中文数字别用 `CN[i]` 取字符** —— `'一二三…十'` 只有 10 个字，
   出到**第 11 天直接 IndexError**，整册渲染挂掉（2026-08-04 实伤）。
   用 `daily_v1.cn(n)`（支持 1..99）。**十天以内的册子看不出这个 bug**，
   所以先写长册的人会替所有人踩到。
4. 🔴 **公式后面的标点会被甩到行首** —— MathJax 的 `mjx-container` 是 inline-block，
   浏览器认为它后面可以断行，于是「…全书的 \(5/12\)。还剩…」把句号顶到下一行开头。
   数学渲染器的 `glue()` 把**公式 + 紧随的标点**裹进 `.nb{white-space:nowrap}`。
   只裹标点、不裹后面的汉字——裹多了长题面会整段推下去，留出一条大白缝。
5. 🔴 **答案卷标题要主动让位** —— 题目卷标题已经快占满版心，答案卷再挂「参考答案」
   四个字必然超宽；而 `h1` 是 `nowrap`，超宽不折行，**直接把外框顶破**，
   左右边框一起跑到纸外。`daily_v1` 的解法：`body.asheet` 整体缩到 0.84 档 + `<small>`。

## 用法样板

册子的 `_源/gen_打卡.py`（真实样板 = `打卡/五升六暑假每日一练/_源/gen_打卡.py`）：

```python
import os, sys
sys.path.insert(0, r'D:\workplace\ai-bkb\.claude\skills\每日打卡\templates')
from punchkit import core, layouts, renderers
import days as dy, qbank as qb

OUT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))

SECTIONS = [                      # 骨架照这个摆版；slot 名由渲染器提供
    {'name': '口算题',   'slot': 'oral',     'grid': 'grid5', 'flex': 0},
    {'name': '脱式计算', 'slot': 'expr',     'grid': 'row4',  'flex': 6},
    {'name': '应用题',   'slot': 'word',     'grid': 'block', 'flex': 10},
]

assert qb.verify(dy.DAYS, quiet=True), '🔴 verify() 未全绿，拒绝出卷'
core.render_book(
    out_dir=OUT, stem='xxx·十天打卡全册', title='xxx',
    layout=layouts.get('boxed_sections'),
    days=dy.DAYS,
    ctx={'sections': SECTIONS, 'renderer': renderers.get('math'),
         'title_a': '五升六数学', 'title_b': '暑假作业《每日一练》',
         'total_days': len(dy.DAYS)},
    expect_pages=len(dy.DAYS), png=True)
```

## 加东西

- **加骨架**（新版式）：抄最近的一份 → 改 CSS/`render_card` → 填 `SPEC`
  → 在 `layouts/__init__.py` 的 `_MODULES` 挂一行 → `python -m punchkit` 确认上菜单。
- **加学科**：抄 `renderers/math.py` → 改 `SLOTS` → 🔴 **把该学科的答案标记补进
  `core.ANSWER_ONLY_MARKS`**（否则「题目卷不泄答案」那道闸对该学科失效）
  → 在 `renderers/__init__.py` 挂一行。**骨架不用改。**
- 🔴 **绝不在册子的 `_源/` 里私长 CSS** —— 那正是本库要消灭的东西。

## 🔴🔴 本库的定位：本地先行，不是过渡方案（2026-08-03 用户拍板）

> **不是什么功能都要往系统里集成。**
> **先本地快速搭工具和管道 → 用起来 → 用久了 → 稳定了 → 再决定要不要合进产品。**
>
> **教训**：太快上线了，结果没什么用、代码还不稳定。上线一次要开 PRD、走部署链、
> 改 BE 模板、动镜像资源——成本是本地改一行的几十倍，而**本地跑三天就知道这版式顺不顺手**。
> 先上线 = 用最贵的方式做试错。

所以：

- 🟢 **本库是正规主路**，不是「PRD-017 落地前的临时替代」。
- 🟡 **上架系统是可选的后置动作**，册子不上线照样卖。
- ⏸️ **PRD-017（版式两线合一）暂不推进**（用户明示「先不管线上，且不上线上了」）。
- 🔴 **别把"和线上一致"当质量标准** —— 线上现在没跑通到值得对齐的程度。
  版式好不好，看的是**印出来好不好用、孩子写得开不开**。

`daily_v1` 虽然移植自线上 `punch-v1`，但**定制后已不等于线上那套**（页码替天数、水印可拔插、
标题小标题参数化）。它是本地的东西，按本地的需要长。

**真要上线的那一天**：那时是「把本地已经稳的版式搬到主题文件」，不是「让本地迁就线上」；
且**要开 PRD 卡走部署链**，不是本地加个文件就完事。
